# R2-B ② 调查证据（仓库与上游实测 + 竞品）

**失败今天能落在哪里**：composer notice（`packages/client/ui-conversation/src/client/contract/input.ts:243-247`，写入于 `packages/client/ui-conversation/src/client/input/facade.ts:554-557`）；`promptError` 错误条（`snapshot.ts:99`、`session.ts:282,342`、`InputBar.tsx:55`）；Toast（`ui-primitives/src/Toast.tsx:62`、`AgentPresetSeat.tsx:201-211`）；transcript flow node（`GenericCommandCard.tsx:10-36`、`packages/client/ui-chat/src/client/locale.ts:101,209`）；会话日志（`interaction/commands/src/types.ts:96-118`）；面板内联 `<p role="alert">`（**实测 26 处 / 13 文件**，如 `GoalBar.tsx:96,133`、`AgentPresetSection.tsx:133,199,234`）。
**落不进去的**：非 composer 面板没有**共享**失败通道（各写各的）；**没有任何 diagnostics / 日志查看界面**；**未进入 handler 的准入失败没有任何日志记录**（`ui-commands/src/client/service.ts:381-391`）⇒ 对它们说"去看日志"是**假指引**。

**文案惯例**：每包一个 NS + zh/en 字典 + `LocaleNamespaceMap` 声明（`ui-sidebar-tasks/src/client/locales.ts:1-40`），`t` 经 `TranslateNS<NS>`（`ui-slots/src/index.ts:76`）或 `PropsLocale`（`:90-93`），由 `scripts/verify-client-ui-i18n.ts:1-13` 强制（JSX 文本与 copy 属性一律拒绝）。错误→本地化：外壳本地化且带参、理由保留宿主原样 —— `switchRefused: 'Could not switch to {name}: {reason}'`（`ui-agent-preset/locales.ts:59,117`），`{reason}` 取自 `error.details.reason`（`seat-store.ts:160-176`）。

**可用性谓词**：`CommandDescriptor` 今天只有 name/description/input（`interaction/commands/src/types.ts:57-64`），宿主不广播可用性。三选一成本：① 客户端本地谓词（最便宜且**已有先例**：`seat-store.ts:109` busy 守卫、`:155` 丢弃不可服务的 stage），但只是 UX 守卫 —— `packages/preset/agent-presets/src/index.ts:678-679` 明言"客户端的 busy 标志不是 enforcement：wire 可被直接打到"；② 宿主随 `commands.list` 提供 availability 字段（新 wire 字段 + 版本化；不含模型可见输入，故**不受**"模型可见⟺已记录"约束）；③ discovery-by-failure（违反 GNOME HIG 与第 1 轮规则，否决）。**采用 VS Code 的 `when`/`enablement` 拆分**。跨插件约束：`packages/client/AGENTS.md:36` 禁止运行时导入其它 feature plugin 的值 ⇒ 谓词只能由面板**已持有**的 props/`useSession`/投影派生，或由注入服务提供。

**三态协议（不碰冻结 bool）**：`{matched:boolean}` 原样保留（`contract/session.ts:138-140`、`sessions/session.ts:372-376`、`ui-conversation/src/client/apply.ts:373-378`）。① **未匹配** = `execute` 返回 `undefined`，仅当语法或名字不解析（`interaction/commands/src/index.ts:362-364`）→ 立即本地反馈、**无日志记录**，文案必须说"没有这条命令"；② **被拒** = typed RemoteError 的 code + `details.reason`；③ **执行失败** = `CommandResult.kind:'error'` 且宿主已落 `command/done`（`index.ts:368-392`、`types.ts:96-118`）→ 内联 + "查看日志"指向该条记录。**日志入口只对 ②③ 成立**，① 必须明说"什么都没记"。
补强：`runDetached`（`ui-commands/src/client/service.ts`）把 `matched:false` 折成 `kind:'error'` ⇒ 客户端在那一层**尚无法区分 ① 与 ③**，类型化结果必须先贯穿。

**"什么都没做"的死结**：`cancel()` 只回 `{accepted:true}`（`contract/session.ts:112`；`sessions/session.ts:333-346` 仅在 !ok 时写 `promptError`）⇒ "已完成"与"已受理"不可区分。要区分的四态：**已完成**（幂等成功、info 级，不说"失败"）；**不是你的**（跨会话/owner，宿主已有 owner 概念 `session-controller/src/agent.ts:80-90`）；**被拒**（策略，typed code）；**中途失败**（已落 error + text，可复查）。

**竞品（本轮实测）**：VS Code 用 `when` 管可见、`enablement` 管可用，"applies to all menus and to registered keybindings"，命令面板隐藏禁用项而右键菜单显示为禁用（[command guide](https://code.visualstudio.com/api/extension-guides/command)、[contribution points](https://code.visualstudio.com/api/references/contribution-points)）；VS Code 对未知命令 `Promise.reject(new Error("command '<id>' not found"))`（仅源码，未文档化）；Apple HIG 让不可用菜单项置灰而菜单仍可打开 "so people can open it and learn about the commands it contains"（[menus](https://developer.apple.com/design/human-interface-guidelines/menus)）；GNOME HIG 原句 "Make invalid buttons insensitive, rather than showing an error message when the user clicks them"（[buttons](https://developer.gnome.org/hig/patterns/controls/buttons.html)）；GTK `set_sensitive`（[docs.gtk.org](https://docs.gtk.org/gtk4/method.Widget.set_sensitive.html)）；clig.dev 的 exit code 与 stderr 约定。

**未判定**：VS Code Problems 面板与通知的分流；`showErrorMessage` modal 语义（文档截断）；Material 3 禁用态规则原文；"no-op 算成功还是失败"的权威 CLI 规范。
