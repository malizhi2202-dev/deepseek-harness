# action-seam 实施清单（两轮结论合并，按依赖排序）

来源：本目录 `n1-principal/`、`n2-discoverability/`、`r2-connection-authority/`、`r2-failure-landing/` 四组结论，以及上一议题 `../sidebar-asks-2026-09-17/` 的 `99-roadmap.md`。每条都注明**改什么 / 依赖什么 / 验收证据 / 不得做什么**。

> 通用约束（适用于每一条）：不新增人类主体；改会话状态的动作**必须走命令路径**；面板只推荐**一个**下一步动作并说明理由；归因未知时**禁用而非警告**；客户端 UI 文案由 locale 拥有；`Model-visible ⟺ logged`；注册一律经 `ctx.effect()`；不新增绕过 owner 栅栏的路径。

## 0. 前置：任何"用户发起的状态变更动作"上线前必须完成

| # | 改什么 | 依赖 | 验收证据 | 不得做什么 |
| --- | --- | --- | --- | --- |
| P0-1 | `cancel()` 从 `{accepted:true}` 改为**判别结果**（如 `stopped \| nothing-running`） | 无 | "已结束"与"已受理"可区分；"什么都没做"可被表达 | 不得改变 `SessionFace.command` 的冻结布尔 `{matched:boolean}` |
| P0-2 | **模式判定 + 启动打印**：load 时判定"模式 A（token→cookie）/ 模式 B（显式无认证）"，并打印生效模式与**生效信任面** | P0-3 同址（`dsh-client-connection` plugin load） | 启动输出点名模式与信任面；**模式 B 时**"认证已关闭"**响亮**可见 | 不得只在文档里说、启动时不打印 |
| P0-3 | **bind ↔ 信任面一致性检查**：loopback bind 时警告「所列授权在本次 bind 下无效」；通配 bind 的分支按 **P0-5 从 schema 移除后即不可达**（保留为防御性文案，不实现） | 无 | 存在一条断言，当某条信任授权无法从当前 bind 送达时报出 | **不要**写「loopback 下 `trustedHosts` 必须为空」（假门：围栏对 `isLoopbackHostname` 无条件放行）；不得拒启（存量安装可能已是 0755） |
| P0-4 | **逃生门判据从请求 Host 头改到实际 bind** | 无（安全必需） | 远端伪造 `Host: 127.0.0.1:<port>` **不再**获得免认证 | 不得继续用可伪造的请求头做"本地性"判据 |
| P0-5 | 把 `0.0.0.0` 从 webserver schema 移除，使"绑定即边界"结构化 | 无 | 改 cordis 文件无法再静默放宽绑定 | 不得保留"命令行拒绝、文件允许"的不对称 |

## 1. 侧栏治理（前置，来自上一议题阶段一）

- **元数据最小集**：`visibility?`（默认 `available`）、`icon?`（默认展示的 tab 必填）、core band 内**唯一** `order`；`badge?` thunk 与 `section?` 推迟到第三次需要时。
- **预算**：`maxDefaultVisible`（默认 3）+ 白名单，做成**消费方 `Config`** 且**必须在设置界面可编辑**。
- **新 gate** `verify-sidebar-right-tab-types`（断言元数据、唯一 id/order、body/title 座位、`dsh-resource://<kind>/` 地址域）。
- 验收：新增面板不靠改核心即可默认隐藏/显示；超预算时"+"页给出类型选择器（纯增量，无迁移）。

## 2. MVP 竖切面：失败归因 +「跳到失败事件」

依赖：P0-1（动作上线前置）、第 1 节（面板可注册）。

1. **`session-outcomes` 投影**（新投影单元；推荐而非"复用现有字段"）：锚点 `{seq, turn, step?, callId?, authority}`；**不可知项必须具名**（无 `hostFailures`/`gatewayFailures`，单一 `unattributed` 桶）；`llm/retry` 恢复的失败是**证据不是权威**；窗口外显示"解释未加载"；级联只画**可证的两类边**，推断边用虚线并给计数。
2. **「跳到失败事件」动作**：走**类型化客户端调用** `loadThrough(seq)`（纯读、零依赖风险），**不**包成命令（避免假审计）。
3. **面板只推荐一个下一步**并给理由；`unattributed` 时**禁用**该按钮。
4. 验收：按钮文案**逐项列出恢复什么、不恢复什么**，且该文案是**被测试断言的字面量**；失败时说清"什么都没做"。

## 3. 回滚检查点（跟随迁移决策）

依赖：第 2 节（跳转是回滚的前置）、**迁移决策**（`dsh-checkpoint-rewind 0.5.2` 精确钉 `0.1.0-rc.6`，既非当前线也非 0.1.5 线）。

- 两段式 **preview → 确认**；落 `command/run`+`command/done`；走命令路径以获得 owner 身份。
- 验收：文案说明恢复/不恢复范围（外部证据：Claude Code `/rewind` 不恢复 bash 改动与多数子代理改动；Cursor 只回文件不回消息）。
- **不得**在迁移未定前，把一个"唯一自带可逆保证"的动作建在声明已不兼容的插件上而不记录该事实。

## 4. 面板（在 MVP 之后）

- **智能体派生面板**：独立 tab **类型**（已验证：guide 盒子由它打开的类型贡献且只带 `kind`，做成镜头会不可发现或打开错页面）；只读依作废处按第 3 轮翻案执行。
- **成本面板**：token/耗时/上下文占用 + 未定价态 + 可编辑价表；**默认不显示金额**。
- **评估面板**：只展示派生事实；**基本不翻**第 2 轮结论。
- **失败归因面板**：见第 2 节（它同时是动作的锚点）。
- **检查点时间线**：分源泳道（V1 只做检查点源）、"时间未知"桶、"不替代版本控制"声明、"创建检查点"动作。
- **只读终端观察面板**：需要一个新的**只读 RPC**，把浏览器请求映射到**所属 Agent**，**绝不接受客户端断言的 owner**；真终端（PTY 挂载）明确推迟。

## 5. 迁移轨道（与动作 MVP 解绑，四前置照办）

1. 理由摆正：**被甩下的是这棵树自己**（插件已跑到 `^0.1.5-rc.1` 线）。
2. **独立 `DSH_HOME` 整份副本**验证（`sessions`/`storages` 在 `DSH_HOME` 级，只换 profile 不隔离日志）；先确认"新线**打开** v2 会话是否就会写出 v3 后继文件"。
3. **先证实迁移源谱系**（远端是个人 fork；`master 47f9438` 是否确为上游支持线 —— **必须用 `git ls-remote` 现场复核**：本仓库是浅克隆且 0 tag，本地 `origin/master` ref 会停在陈旧提交，按本地 ref 判断会误判）。
4. 出具"**迁移后免费 / 仍需自建**"清单。

已知单向门：新线写过的会话落 v3 generation，0.1.3 线读不了。

## 6. 独立议题（**不得**拿面板当理由扩大产品命令面）

- **停后台 job**：只差一个 Consumer（slash command）；`CommandInvocation.agent` 即 owner 身份；面板主语必须是"面板所属会话"（subagent 自有 job 被栅栏有意排除）。
- **派生修复子代理**：同样只差 Consumer；另依赖第 2 节的"失败上下文包"。

## 7. 明确推迟（本轮不做）

真终端 / PTY 挂载；`availability` 线字段（无消费者证据）；`badge?` 与 `section?`；把动作注册表做成新 client 服务；改动 `SessionFace.command` 的准入布尔；信任清单裁剪（负责人选择"只声明不改配置"）。

## 8. 仍未决（不擅自决定）

逃生门最终形态（换名 opt-in / 保留原名 / 直接删并让脚本走 token）；`cancel()` 新返回值的兼容与迁移路径；outcome 原语放 `ui-primitives` 还是各面板自持。
- **不收口不得上线动作**：「必须落域事件」是门还是刹车 —— `goal/change` 无 actor 的反例今天会被放行（见 `00-subtopics.md` 未决①）。

## 9. 残余风险

- **模式 A**：认证在链路上；风险集中在 token 兑换与 cookie 生命周期。
- **模式 B**：认证不在链路上，任何本地进程或浏览器扩展可直达全工具 API；承担该风险的是**部署方选择的绑定地址**，不是认证。因此"绑定被放宽"是一个**会同时打开这扇门**的动作。
- **文档边界**：档内只记产品层事实；实例的部署取值与启动参数不入方案、不入代码，也不作为断言依据。
