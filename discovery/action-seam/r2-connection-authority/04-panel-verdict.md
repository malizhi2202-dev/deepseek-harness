# R2-A ④ 专家团评审（含中途到达的 live 证据）

**判词**：1 有保留 · 2 **反对"已结算"** · 3 **反对保留为未记录的静默全绕过** · 4 同意"宣布为支持"并更正 R2-A · 5 有保留。

- 第 1 条：同意把"最小诚实契约"写成文档，但**现稿第一句假定了一定存在一枚已签名 cookie**，与产品实际存在的两种模式不符 ⇒ 契约必须**按模式分支**：模式 A（token→cookie + 回环 + 围栏）/ 模式 B（显式无认证 + 回环 + 围栏），并写明模式 B 下"Host 是回环就等于『是你』"。"不得静默"必须落成**启动打印模式与生效信任面**；文件权限断言须落在路径的所有者处，形式为**点名路径的响亮警告**而非拒启。
- 第 2 条：**反对"已结算"** —— 它不是未言明的假设，而是**对出货配置事实不成立**。结算不需发明授权层，只需：load 时判定模式 + 两模式各有断言与测试 + 文档写明模式 B 含义。做到即当天可结；第 1 轮的僵局（发船 vs 先闭合）**在成本上是假的**：闭合它花的是断言与文案。
- 第 3 条：**门必须从请求 Host 头改到实际 bind**（理由见 03 的独立一条）；形态三说未收敛。
- 第 4 条：同意宣布共享 `$DSH_HOME` 为支持，但同时**更正 R2-A** 的"cookie 互通"（跨端口不互通，sessions 根才互通）。
- 第 5 条：不对称本身是缺陷；"bind 是唯一边界"是**安全不变量**，下游任一项都不能替代它 ⇒ 文件路径要么在 load 时以同文案拒绝，要么每次 `0.0.0.0` 启动打印暴露声明，**二选一**。

**分歧清单（不抹平；★ = 中途证据到达后新增或改向）**：① ★ 第 1 层是"未证"还是"不存在"（John 契约照写 / Winston 说 live 里缺省关闭 / Mary 要 A/B 两模式分别验收）；② ★ 断言强度（Winston 拒启 / John 警告不阻断 / Mary 警告可机器验证）；③ ★ `trustedHosts` 空 vs 惰性（Winston 认为是假门 / John 认为那就别写）；④ 信任清单裁剪权归部署所有者还是安全不变量 —— **未收敛**；⑤ 逃生门力度三说 —— 未收敛；⑥ ★ 共享 home 的 cookie 互通说法被实测否决；⑦ 计数漂移（见 R2-B）；⑧ ★ 实例部署取值的权重 —— **不适用**：档内只记产品层事实，实例的部署取值不作证据。

**每位视角最该改或砍的一处**：产品经理 —— 砍掉 `start-web-local.sh:61` 里那行看不见的 `NO_AUTH`，把"无认证"变成启动时看得见的一次选择；架构师 —— 把逃生门的判据从可伪造的请求头改为不可伪造的 bind，并砍掉 loopback bind 下那些惰性授权（若信任面被放宽到通配 authority 或全局 IPv6 条目，它们制造"存在信任清单"的假象）；分析师 —— 契约按模式分支，砍掉"共享 home ⇒ cookie 互通"这条与实测相反的断言。

**架构师开工前必答项**：① 模式判定点、断言位置、启动打印内容；② 逃生门的门是 bind 还是 Host、谁有权设置；③ 信任面归属（属**部署所有者事务**）；若允许通配 authority 或全局 IPv6 条目，其合法性由谁裁定；④ bind–信任面一致性断言的确切文案与拒绝/警告级别；⑤ 文件权限由哪个所有者检查；⑥ 出货配置下 cookie 层是否根本不走 —— 若不走，它的绿灯测试是"路径已死"的证据，须明说；⑦ `cancel()` 判别结果先于任何动作上线（见 R2-B）；⑧ 出现真实消费者前不加 `availability` 线字段。

**验收口径（采纳，可机器验证）**：(a) 启动输出点名生效模式与生效信任面；(b) loopback bind 下非回环 Host → 403；(c) 无凭据请求成功，**当且仅当** bind 是回环**且**模式是显式选择且被打印；(d) 存在一条断言，当某条信任授权无法从当前 bind 送达时报出；(e) 文档含模式对照表；(f) 共享 home 下"一个 session 的 cookie 能读到另一个 session 的数据"写成已知后果并有测试。

**产品经理的补位提问**：「谁能动作」没有结算，round 2 把它换成了更锋利的问题 —— **不是「主体是谁」，而是「这个实例此刻处于哪种模式，操作者能否看见」**（从身份问题移到可验证的部署状态）。附带第二个未答：**在无认证模式下，任何用户可见的状态变更动作能否上线** —— 这才是 PM 真正的闸门。

**会让用户动作变危险的事**：(i) 无认证模式下上线动作而操作者不知情；(ii) 任何能被「操作者没在打印 URL 打开的页面」触发的动作；(iii) 逃生门的判据仍是请求头；(iv) 放宽绑定与逃生门同时成立；(v) 成功/失败文案指向一条并不存在的日志记录。

**五条改变条件**：① 逃生门被替换且部署复验后，第 1 条降为同意；② 逃生门删除且启动行声明生效边界后，第 2 条即同意，发布日期不受影响；③ 保留原变量名但门改为 bind 判定、启动打印模式、脚本改为可见传参，则接受沿用现名；④ 出现第二个主体，则「共享 `$DSH_HOME` 宣布为支持」转为缺陷；⑤ 产品放弃 LAN 服务，则第 5 条改为 load 拒绝、无需暴露声明。

**逃生门的处置意向（本轮正式稿此前丢失，据专家团记录补回）**：专家团**反对保留为未记录的静默全绕过**，主张**换成显式二次 opt-in**，并**同时把门从请求 Host 头改到实际 bind**（理由见 ③ 的独立一条）；`scripts/start-web-local.sh:61` 那行看不见的环境变量应改为启动时用户看得见的一次选择，并在 URL 行下加一句边界声明。*改变条件*：保留原变量名但门改为 bind 判定、启动打印模式、脚本改为可见传参 —— 则接受沿用现名。
