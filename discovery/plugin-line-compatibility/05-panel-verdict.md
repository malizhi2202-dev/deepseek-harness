# 插件目标线兼容：④ 专家团评审

**判词：同意 1 · 有保留 2 · 反对 0**（产品视角同意整体取向｜架构与业务分析视角有保留）。

名册解析需写盘，与本轮只读约束冲突，故退到三视角并声明偏离。编号纪律：分歧记 `G1–G7`，与 `02-brainstorm.md` 的方向 `D1–D20`、`01-verified-facts.md` 的事实 `F1–F19` 不撞号。

## 一、各视角的五答

### 产品视角（同意）

1. **同意**：R1 不是新特性，是既有规则欠账——挂起无超时与「never silently skip a missing referent」相冲突，永远等待的纤维就是被静默跳过的引用。
2. **最该砍**：R4 在本仓的实现野心（证据表明核心加载期根本不知道自己处理的是「第三方按版本装入」的插件）。
3. **必答**：R1 的输出面归谁——候选三方各有主，需客户端栈所有者与装载器所有者共同裁决。
4. **会误解的事**：把「未激活」当成唯一失败形态，会掩盖其他在更晚、不同点失败的注册面。
5. **翻转条件**：若证明加载期拿不到插件清单，则 R4 与 R1 的落点都要重排。

### 架构视角（有保留）

1. **有保留**：整体方向成立，但两个「貌似便宜」的项落点不存在。
2. **最该砍**：**R2**。清单类型包无运行时校验器，且自述「每个读者自负校验」⇒ 要报告「未知清单字段」必须新建**全命名空间所有者**；而字段按读者分片，新读者会先被判「未知」从而制造误报；报告还会诱导用户删掉前向兼容声明。
3. **必答**：R1 的实现范围须先由依赖源码的所有者裁决「只许观察侧，还是允许改动依赖源码」。
4. **会误解的事**：一个读不到字段的校验器会**空转通过**，输出与校验成功无法区分。
5. **翻转条件**：若将来改为能力探测，则 R5 可以复活。

### 业务分析视角（有保留）

1. **有保留**：程序上有两处越位风险。
2. **最该砍（移出）**：**R3**。清单自述「每个读者自负校验」与把它称作「权威 schema」互相矛盾；矛盾未解前，任何相关文案都缺权威依据。把词表归属塞进插件兼容议题，等于让提议者替词表所有者签字。
3. **必答**：R1 的输出面与「来源列」从哪来——因为既有投影的视图是**不完备**的。
4. **会误解的事**：把「声明」当成「承诺」——用户会以为写了目标线就意味着核心会校验它。
5. **翻转条件**：若把词表归属与安装落点先裁掉，剩下的窄项可以同意。

## 二、圆桌独立得出的结论（原稿未点明）

**两个「貌似便宜」的项死于同一病因——落点不存在**：

- **R2** 没有全清单校验器（F10），且既有解析器的视图不完备（F8 的返回值可为 `undefined`），给不出完备视图。
- **R4** 没有市场实体（F19）。

因而正确顺序是：**先修看得见的，再定谁说了算，再分配谁来管，最后才谈要不要报告／要不要拦截。**

## 四、三视角一致同意

1. **R5 现在不做**：F15 与 F16 使朴素的版本判定会先把当前树自己判为不兼容。
2. **匹配规则必须收进单一纯函数**，并以 F15 四组为**准入用例**。
3. 任何安装期判定前必须先裁清两条安装路径的 peer 设置漂移（F17）。
4. 不改会话格式、不改挂起语义、不引入上限字段。
5. 本议题若不带完整判定规则，则只能以窄形态过门。

## 五、专家团给出的排序

**R1 ＞ R3（移出但为前置）＞ R4（只留登记并移交）＞ R2（降级为可选）＞ R5（冻结并附复活条件）**。

## 六、进人工审核门的判定

**可以进，但只能以裁剪后的窄形态进**：R1 可独立过门；必须携带 R2 与 R5 的否决记录（否则下轮重提）。若门要求「本议题自带完整判定规则」则不能进，缺：词表权威性张力、纯函数包的归属、R1 输出面与来源列的归属。

不建议以「先做个版本检查试试」过门：F15 与 F16 已证明第一个判决就是错的。

## 七、程序建议

**拆分三条路**：

1. **R1 独立立项**——它是既有规则欠账，不需要市场议题的任何裁决即可实施；绑进市场议题会让今天就能做的修复无限期悬置。
2. **R2／R3／R4 并入既有的插件准入／市场议题**——既有风险条目就是该议题现场。
3. **R5 不立项**，只留否决记录与复活条件。

保留意见：架构视角主张 R1 与 R3 同案（R1 的文案措辞可能隐含「该声明本应被强制」，需 R3 的语义约束用词）；产品视角反对绑定。该点应由人工审核门裁决，不由本议题默认合并。

## 八、主 agent 对专家团的三处更正

专家团评审时不知道以下事实，故其 R1 相关结论需按下表修正：

1. **R1 已被既有能力取代**：挂起状态**已经可见**（F12：既有投影逐入口暴露根纤维阶段，含 `pending`，且有设置页客户端）⇒ 「R1 是本议题唯一可立刻做的事」**不成立**；本议题的静默只剩**成因**那一格（F13、F14）。
2. **R4 的理由要改**：本仓**有**插件状态面，但它被设计为**只读、无变更路径**（F19）⇒ 结论（无安装期落点）成立，理由不是「不存在」而是「存在但被明确设计为只读」。
3. **一处措辞以文件为准**：清单类型包的自述是「**每个读者自负校验**」（F3），故先前「权威 schema」的说法作废，专家团据该说法展开的论证相应改为「共享词表」。
