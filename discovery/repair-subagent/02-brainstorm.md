# 02 · 头脑风暴（S1–S4）

来源：子代理按 `bmad-brainstorming` 的三视角（PM / 架构 / BA）展开，本文件为收敛后的记录。方向编号 D1–D20 按子议题分组，保留可判定的分歧，不合并同义项。

## 方向清单

### 组一 · 上下文包（S1）

| 编号 | 方向 | 关键点 |
| --- | --- | --- |
| D1 | 纯投影组装：从既有事件算出失败上下文，不改格式 | 依赖能否从 `turn/end` + `tool/result` + `assistant/attempt` 还原 |

| D6 | 把失败上下文包做成新的模型可见输入 | 若采纳，触发 F12d 的会话事件问题 |

## Top 5（收敛结果）

1. **D2 + D3 组合**：结构化字段 + 必填未知项 + 坐标引用而非正文转发。
2. **D1 作为实现前提**：先证明纯投影可算，再谈载体。
3. **D7 定人类入口形态**：会话内手势 + 宿主解析主体。
4. **D12 / D13 / D14 升格为设计前提**：只读要能强制、拒绝要不可翻回、预算要显式。
5. **D20 + D19 作为降级路径**：不可知时宁可只报告。

## 反例与危险假设

- **最危险的假设一：失败只有一个坐标。** 失败可能是序列（重试若干次后终局），单点模型会把序列压成一点。
- **最危险的假设二：「子代理能读全上下文」。** 事实相反两头都错：它**看不到**父对话（除 fork 型 provider），却**能到达**整棵工作树（F10c）。
- **最危险的假设三：「委派是轻量动作」。** 委派是本议题中**唯一不可逆的动作**：子代理审批被钉成 never（F9a）、写范围由沙箱决定、预算不受父约束、范围从内部不可改。

## 分层结论

- **纯投影即可完成**：10 项（D1、D3、D5、D18 的一部分等）。
- **需要新写入端但不改事件契约**：9 项（D2、D7、D12、D13、D14、D16、D20 等）。
- **需要新事件**：只有 D6，且它被描述符版本纪律挡回（F7b）⇒ **本议题不需要新增会话事件**。

## 交给 ③ 的未决项

3. 人类触发的派生要不要让父模型看见（决定 D6 是否复活）。
