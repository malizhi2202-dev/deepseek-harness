# 99 · 落地清单

本议题**不需要新增会话事件**。工作量属第二档：需新写入端，但不改事件契约。唯一的格式级候选是 `04` 的 R4（给描述符加失败来源），已排队。

## 一、门内裁决（已定，直接执行）

- [ ] 修复者首发**默认只读**：产出结论与建议，不改工作树。
- [ ] 需要写时**必须人类同意**；人类未同意前，写类工具对该修复者不可用。
- [ ] **派生动作用本身是危险动作**：必须人类确认；**入口不得是命令**（`04` 的 J4）。
- [ ] 上游未决项不作为前置，不阻塞本议题。

## 二、R1 · 失败上下文包与只读接力（先做）

- [ ] 上下文包字段落地为「结构字段 + 必填具名未知项」，模板照 `01` 的 F8，并在实现说明里写明它原本是冷加载合成的工具结果（扩大适用面）。
- [ ] 坐标引用优先于正文转发：会话、turn、step、事件 seq（`01` 的 S1 素材面）。
- [ ] **保留原失败 run 的日志与状态**，不得因修复成功而消解失败证据（`03` 的 E19 反面）。
- [ ] 只读通过组合层工具过滤落实；可续跑子代理的过滤会随描述符持久化，一次性子代理不会（已知不对称，需在文档写明）。
- [ ] 单调工具守卫作为兜底，并证明拒绝不可被后续监听者翻回。
- [ ] **零代码对照实验**：先用现有委派工具 + 结构化 brief 跑一轮，验证上下文包是否真的够用；该实验的结论决定 R1 是否还需要新写入端（对应 `05` 的 G1）。

## 三、R3a · 显式次数与预算（随 R1 一次带上）

- [ ] 派生请求带显式次数上限与预算，复用既有递归闸门，不新造机制。
- [ ] 写明冷恢复**不继承**原预算、也不继承父当前预算（`01` 的 F10e），因此预算是本次激活的约束而非持久保证。

## 四、R2 · 人类入口（在 O1–O3 有答案后）

- [ ] 人类侧与模型侧作为**两个独立注册的能力**，不共用通道。
- [ ] 人类手势以消息来源判定可信度，外部文本不可伪造。
- [ ] **主体由宿主解析**，不接受客户端自报；形状参照既有的权限枚举。
- [ ] 审计落点另行设计：不得通过「包成一条命令」获得审计（`04` 的 V2）。

## 五、R3b · 后续边界（等真实压力）

- [ ] 补按父级并发上限。
- [ ] 写类能力一律落在人工确认之后。
- [ ] **发起派生的一方不得自批**。
- [ ] 先写规则后写代码。

## 六、R4 · 排队（唯一格式级）

- [ ] 给描述符加「失败来源」输入（版本变更），等第二个消费者；在此之前保持现状。

## 七、门后仍开放的三项

| 编号 | 开放项 | 需要的决定 |
| --- | --- | --- |
| O1 | 「只读」禁哪些工具、谁来配 | 组合层过滤的默认集与可配置面 |
| O2 | 人类触发的派生是否需要父模型可见 | 需要 ⇒ 引入 surface 事件，R2 升为格式级；不需要 ⇒ 父子可见性仅存于子日志 |
| O3 | 宿主侧主体解析的具体设计 | 面板所属会话 → 主体的解析路径与失败处理 |

## 八、完成判据

- 只读修复者能由一个已确认的人类手势派生，产出带具名未知项的结论，且**不触碰工作树**。
- 关闭该修复者后，原失败 run 的日志与状态仍完整可读。
- 递归深度、次数与预算三项在派生请求上可见且有默认值；越界时是可读的拒绝而非静默截断。
- 未引入任何新的会话事件类型。
