# ③ 结论与建议

**结论：本议题**不是**格式级改动 —— 步级「是否正常收尾」是纯投影可判定的谓词，先做投影竖切面；`step/end` 加可选 `outcome` 只作为独立增补提案排队，`authority` 随它走。**

## 判决依据（事实编号见 `01-verified-facts.md`）

1. **判据已经存在，只是被丢弃**：`step()` 的结局类型在源码里就有（`StepEndReason`），`stepEnd` 在该步被取到后只把 `max-tokens` 折进 turn 级累加器，写 `step/end` 时丢弃（F1、N1）。⇒ 缺的不是「算不出来的信息」，而是「没人把 fold 规则写下来」。
2. **模型层失败原因也已落盘**：`stream` 原样保留 `finish` chunk，其 `error`/`aborted` 自带 `failure: LlmFailure`（F2）。⇒ 失败原因不需要新字段。
3. **可判定谓词**：`step/end` 由 `finally` 保证每步一条，正常 return 之前必落 `assistant/message`；唯一例外是「中断但有内容」（F3、N8）。⇒ 「有 `step/end` 但该步无 `assistant/message`」＝未正常收尾。
4. **可判定 ≠ 可归因**：工具失败只半结构化、shell 退出码要正则反解（F4）、崩溃合成的 `step/end` 无任何标记（F5、N6）、错误可能来自 step 体外（R7）。⇒ 归因必然留下一部分 `unattributed`，必须**具名**而不是猜。
5. **「格式级」两档代价差一个量级**（F8、N3–N5）：payload 增补旧构建不拒读；新增事件类型会让旧构建整条拒读。上一轮把两者混为一谈，是本议题被误判为「格式级」的根因。
6. **外部先例一致**：12 个系统无一用纯推导定义执行单元终局；OTel 的 `Unset` 先例判决「字段缺失绝不能被读成成功」（`03-competitive-recon.md`）。

## 推荐（按序）

| 序 | 切片 | 内容 | 关键约束 |
| --- | --- | --- | --- |
| **R1a（先做）** | 纯投影，零格式改动、零快照 churn | 四格谓词（`completed` / `max-tokens` / `null` 未 conclude / `interrupted: true`）+ 从 `finish` chunk 解失败原因 + **合成事件检疫** + `unattributed` | 检疫**必须显式承认为「结构性缺席推断」**，不得称零代价（N6）；`authority` **不在本片** |
| **R1b（紧随）** | 修今天已错的用户可见归属 | 用 R1a 的谓词替换两处 `steps.at(-1)`（函数体逐字相同，抽一份共享助手） | **依赖 R1a**，不得当独立小改（否则同一处 UI 改两遍、第一遍必写错）；`turn-process.ts` 的 `at(-1)` 是「最新步」语义，**不得一并改**（N7） |
| **R3（排队）** | `step/end` 加**可选** `outcome` | 唯一直击权威坐标的改动；`authority` 随本片走 | 前置裁决「**工具失败是否算步失败**」；须同步冻结成员清单（N3）、三条 close 路径一致（正常 `finally` / catch / `repair` 合成 —— 后者**原理上无法知道结局**，必须定义它写什么）；明确 step 是步级结局的唯一 home |

## 否决记录

| # | 否决项 | 理由 |
| --- | --- | --- |
| V1 | 「本项目属于格式级改动、须**新增会话事件**」（上一议题交接项的判定） | 最重、无必要，且会让旧构建**整条拒读**（F8、N5）；主体工作落在投影层 |
| V2 | 「只加一个布尔 `ok`/`failed`」 | 源头终点本就是**三态**（N1），加上工具层与合成路径共两层，布尔必在崩溃合成处**说谎**（F5） |
| V3 | 「给 `turn/end` 加 step 坐标」 | `max-tokens` 粘滞折叠下坐标**不唯一**：turn 跨多步时「那一个步」没有数学定义；且 step 体外错误无步可归（R7） |
| V4 | 「今天就加 `step/end.outcome`」 | 无第二个独立消费者，纯投影已够服务 R1a；与 R3 排队**不矛盾** |

## 未决（保留，实现前必须收口）

1. **R1a 的验收标准**：其消费者 `session-outcomes` 投影在仓库中不存在（N9）⇒ 需先把该投影的需求落成仓库内可引文档（见 `06-review-record.md` 的门内待裁决）。
2. **`authority` 归属**：门内已裁决**随 R3 走**；R1a 期间按「不可知项必须具名」处理。
3. **工具失败是否算步失败**：R3 启动前的硬前置；若与 F4（结构化工具结局）同批解决，R3 须提前。
