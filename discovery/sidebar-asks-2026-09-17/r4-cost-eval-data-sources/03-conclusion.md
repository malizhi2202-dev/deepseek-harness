# 成本/评估观测数据源 ③ 结论与建议

**一句话结论：本议题是增量复核，不重开既有决策；三条决策面的新增事实是「会话级用量丢了桶额到路由的归属」「输入 token 口径与外部规范相反」「外部规范已把评估标准化为一等事件」，且本议题不需要任何格式变更。**

## 一、先说明本议题与前作的关系

第 1 轮的 S3 子议题（`../s3-cost-and-evaluation/`）已过门批准，其结论仍有效：成本 token 口径可行、金额口径需自带价源；评估只展示派生事实，不显示正确性、评分与通过率。集中决策记录另已覆盖两条：

- 决策 4：成本口径为「token/耗时/上下文占用 + 缺价目态 + 可编辑价表」，金额标 estimate、历史不回填、与实际账单分离。
- **R14「第三方模型无价源」的对策：成本按 token 展示；价目缺失显示「无价目数据」而不是 0**（`../05-risks-and-gates.md:34`，【复核】）。

⇒ 本议题的 R2 与 R4 **不是新决策**，而是 R14 与验收标准 5 的应用。

## 二、三条决策面的新增事实

| 编号 | 事实 | 为什么要紧 | 分级 |
| --- | --- | --- | --- |
| N1 | 会话级用量投影的 wire 是 `state.totals`，**不含 provider/model**；路由信息只存在于每轮 `routes` | 换过模型的会话若用单张价表乘四桶总额，结果**静默错误** | 【复核】 |
| N1′ | 精确化：**路由数据本身并不缺席**（模型选择投影已折 `request/header` 的 provider/model），缺的是**桶额到路由的归属** | 决定补法：不是「再记一次路由」，而是「把桶额按路由拆分」 | 【复核】 |
| N6 | 输入 token 口径与外部规范**相反**：外部规范规定输入**含**缓存，本仓规定三类**互斥**（billed = 三者和） | 两套口径都合法、数字静默不同；面板必须显式声明用哪套 | 【复核】 |
| N4 | 外部规范已把**评估**标准化为一等具名事件（评估名 / 分数标签 / 分数值 / 解释 + 关联键），但**只定义「分数怎么记」，不定义「什么算通过」** | 与本产品「绝不显示评分」直接冲突 ⇒ 需要一条明确的不采纳记录 | 【联网】 |

## 五、推荐

- **R1（先做，形态）** 本议题的产物即本目录五份文件；**不新增第六个文件形态**，不写 `06-*`。
- **R2（成本）** V1 只出 token/耗时/占用，**不出现任何金额**；金额一律按 R14 处理：按 token 展示，缺失显示「无价目数据」。**会话级四桶不得参与任何乘算**，因为 N1 的归属缺口会让结果静默错误。
- **R3（评估）** V1 ＝ 当前会话内的既有逐消息反馈汇总 + 具名缺失态；**不引入分数、不显示正确性/通过率**；跨会话视图不在 V1（见裁决 2）。
- **R4（口径）** 已由 R14 与验收标准 5 覆盖，本议题**不新立决策**；但须在成本面板落地时落实 N6：每个 token 数字标注口径（互斥口径 vs 含缓存口径），并沿用「不把不可加项相加」。

## 六、不重开与不做

- 不重开「金额进 V1 主面板」（既已砍掉，且与裁决 3 一致）。
- 不重开「评估只展示派生事实，绝不显示正确性/评分/通过率」。
- **不因外部规范有一等评估事件就引入评分**：规范只定义如何记录分数，不定义什么算通过；若将来要引入，必须新增持久事件并单独裁决（「模型可见 ⟺ 已记录」义务）。
- 不把基准门与快照回放当评估数据源（N5）。
- 不把价表快照绑进日志（会与「历史不回填」冲突，且是唯一会触发格式变更的选项）。

## 七、残留待办（不影响 V1）

1. **分路由桶额归属是否立项**：这是 N1 的唯一正解，但会新增投影单元且**不得改动既有 wire 形状**。本轮只把它写成风险与前提，未批准立项。
2. **缺失态再细分**（业务分析提出）：「未命中价目」与「该路由本就无价目」在今天会被合成同一个缺失态，用户会读成「忘了配」。建议后续在文案上区分，与裁决 3 合并执行。
3. **`session-outcomes` 的计数权威需与 `sessionStats` 并列声明**（裁决 4 的直接后果），否则两个数字会被当成同一个数。
