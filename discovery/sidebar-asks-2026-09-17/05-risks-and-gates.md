# 风险、流程修正与实现门禁

本文件汇总第④步边界视角（约 43 条）与专家团中可操作的项，供实现阶段直接引用。

## 一、流程修正（立即生效，与本议题结论无关也应遵守）

| # | 规则 | 依据 |
| --- | --- | --- |
| P1 | **区分改动类型**：client-only 改动**刷新即可**（模块按请求取盘、rev 现算）；宿主/组合行改动才需重启 | 事实 C1（复核证据） |
| P2 | **验证实例必须脱离被验证实例的进程树**，并使用独立 `DSH_HOME` | F25（把验证实例作为主实例的子进程并共用 `DSH_HOME` 时，重启会连带杀掉它，且两进程同写 sessions/settings 有覆盖风险） |
| P3 | **验证门写成可观察行为**（刷新→展开→看到入口→数据随会话变化→中英空态），不以"模块 200 / 字节数"作为通过依据 | 边界视角第 15 条；`03` 的验收清单 |
| P4 | **"没问题"必须展开成可勾选清单**，否则无法判定何时可重启/发布 | 边界视角第 1 条 |
| P5 | "先查插件库"必须**同时核对 patch 层的 `disabled`**（已安装 ≠ 已启用），并记录检索词 | 事实 C2 |
| P6 | 未解析术语先进"待澄清"登记并冻结，不进开发队列 | S4 结论（archiy） |
| P7 | 禁止由被重启实例内部执行对自身的重启；重启前确认无运行中的 turn / PTY / job，并保留上一构建与启动参数、检查端口占用、失败即回退 | 边界视角第 5–7 条 |

## 二、设计与行为风险

| # | 风险 | 要求 |
| --- | --- | --- |
| R1 | 子代理目录按需拉取，可能 `undefined` / loading / error，或含 `diagnostic` 条目 | 每个节点显式渲染三态，不把未加载当作"没有子任务"；诊断行 `aria-disabled` 并给出原因 |
| R2 | 点击非健康子项可能抛错（`selectSubagent` 对非健康子项会抛错） | 仅对 `child` 且目录 `ready` 的条目可导航，其余置灰并说明原因 |
| R3 | 图谱范围与深度无界 | 根节点 = 当前会话；递归拉取设深度与并发上界；只保留一个**安全**深度常量 |
| R4 | 根因证据只有 `lastAgentError`（单字符串、prompt 时清空、客户端内存态） | 声明持久证据来源（状态/耗时/失败计数/会话事件），并标注"自恢复的瞬时错误不留痕" |
| R5 | 评估缺值语义未定义 | 固定字段集，`0` 与 `undefined` 区分显示（空白会话不得显示"0 成功"或"耗时 0"） |
| R6 | 评估无窗口与分母口径 | 明确窗口、分母、去重规则；不产出通过率（分母无定义） |
| R7 | 跨会话不展示子会话 todos | 声明该边界，或按需拉取并标注来源 |
| R8 | 终端输出经 `terminal_*` 工具进入模型请求即 model-visible | 遵守"Model-visible ⟺ logged"：模型可见的终端输出必须落会话事件 |
| R9 | 终端会话是 Agent 作用域且仅存在于宿主进程内 | 声明 PTY 随宿主退出；面板显示断连并可重连或新建；不得停在假"运行中" |
| R10 | **终端授权边界未定义**，而 `--trusted-host` 可放宽到非回环 authority | 明确谁能打开终端、是否逐次确认、受信主机上浏览器会话的边界（否则持浏览器会话者即可获得任意 shell） |
| R11 | Git 面板未定义仓库路径来源与异常仓库状态 | 以当前会话 cwd 为准，渲染"无仓库/多仓库待选"空态；对 detached HEAD、无提交的新仓库、rebase/merge 进行中、worktree、未安装 git 逐状态声明只读表现或禁用写操作 |
| R12 | 「git 即为记忆」含不可逆写操作（revert/commit） | 写操作需确认并预演将丢弃的改动；三源合成时必须逐条标注来源（决策 3） |
| R13 | pi 转发的同一模型 `chat/completions` 返回 400 而 `responses` 返回 200 | 按模型声明选择 API，并在 400/未授权时给出可执行错误与降级；不得让"列表里可选、调用必然失败"成为常态 |
| R14 | 第三方模型无价源 | 成本按 token 展示；价目缺失显示"无价目数据"而不是 0 |
| R15 | 与既有 `subagent-model-selection` 及会话内模型选择的交互未定义 | 声明选择粒度（会话/子代理）与冲突优先级，避免两处配置互相覆盖 |
| R16 | 插件检索未定义"符合"的判定 | 增设"装入即验证"的兼容性冒烟门（能启动并渲染），避免重演 `web-ui-*` 因 API 过期被批量禁用的结局 |
| R17 | 多插件提供同类面板时的冲突与去重未定义 | 声明 kind/id 命名约定与"冲突即失败"的处理方式（注册表已对同 kind 抛出错误） |
| R18 | "没有符合的插件自己开发"未定义自研/fork/包装的边界 | 优先包装或上游 PR，仅无维护者时自研，并记录判定依据 |
| R19 | 每个面板未定义数据来源、三态、刷新语义与文案归属 | 每面板一行：来源、拉取方式、空态、错误态、locale 字典归属 |
| R20 | 维护税未计入 | 每新增一个 kind 都需给出"做到什么程度算有用"的验收标准（见 `03` 第三节） |

## 三、实现阶段的门禁要求

新增客户端包与新增 kind 时，按下表执行（均为仓库既有门禁，不新增门禁）：

| 门禁 | 何时必须 |
| --- | --- |
| `verify-export-jsdoc` | 新导出 |
| `verify-package-paths` / `verify-package-invariants` / `verify-package-readme-limitations` / `verify-package-readme-model-experience` / `verify-package-dependencies` | 新增包 |
| `verify-client-ui-i18n` | 任何客户端文案（`zh` 与 `en` 字典、无硬编码） |
| `verify-translation-pairing` / `verify-agent-note-format` / `verify-doc-budgets` | 新增或修改双语文档与 Agent Note |
| `verify-client-packages` | 新增客户端包（三处接线：根 `tsconfig.client.json` 聚合、`packages/bundle/web-app/cordis.patch.yml` 行、该 bundle 的 `package.json` 依赖） |
| `ui-theme` 的 CSS 审计 | 新增滚动容器（不得引用 elevated surfaces；全圆角需同规则内 `corner-shape: round`） |
| keyless 录制会话快照 | 任何非平凡的产品用户可见改动 |
| Agent Note 三件套（`md` / `zh.md` / `i18n.yaml`） | 非平凡改动必须在同一 PR 内（每条新 note 触发一次取代性检查） |
