## 二、对承重事实的更正与加强（C1–C7）

- **C1【更正·承重】**「Web 面不挂终端行」只对 web-app 的补丁文件成立：Web 的 agent 平面由**每会话 agent preset** 拥有，而**可选中**（roster 第 3 位）的 `minimal` preset 已组合 `pty` + `terminal-bash` + pwsh 孪生 + 模型侧持久 shell 工具，并经 web-app 的 `agent-presets` 行（默认 `standard`）与设置页暴露。⇒ 六条前置条件 (1)「目标 preset 确实挂了 PTY 行」**已经满足**；2b 的真实含义不是「挂 PTY」而是「**把既有 owner 会话暴露给浏览器**」。
- **C2【更正·承重·推翻冻结前提】** 冻结记录「传输面只有 fetch/SSE + 远程方法调用，没有 websocket」**为假**：该 WebSocket 路由是既有实现（非本轮新增），宿主侧持有 `noServer` 的升级服务，升级走与 fetch **同一**信任闸，且已有 `@Remote({ mode: 'stream' })` 在该面上发流。受影响的还有「输入／输出／尺寸／重连都要自建分帧」：**输出推送与重连已由该面拥有**，真正缺的只有**输入**（写是行导向而非逐键）与 **resize**（跨三层零命中，只有初始行列）。
- **C3【加强】**「浏览器→Agent 的解析机制已存在」说轻了：承重点是**声明层**（lookup 与 host-context 的配置）与其下的 agent 标识解析——wire 字段名为 `agentId` 而类型是会话标识；已有成品端点以 `@Remote async read(agent: Agent, …)` 形式存在，自述「target Agent resolved from the Session identity on the wire」。⇒「绝不接受客户端自报 owner」**不是纪律而是既有强制点**，满足仓库规则「在做出决定的操作里强制该决定」。
- **C4【更正 S2 表述】**「旁路 LLM 调用完全不受检」只对不变量成立，对**仓库记账习惯**不成立：标题调用在派发前把 system 与 messages 逐字落成 log-only 事件，压缩以成对事件夹住调用。⇒ 旁路的既有范式是**自落 log-only 事件**；采纳子议题的写法会得出「旁路无需事件」的错误推论。
- **C5【更正·证据边界】** 回显注释只证明「写入 PTY 的字节会回显」，**不证明**「人类键入会回显」；后者取决于行规程与读入程序（关闭回显的读入程序是现成反例）。故密钥风险限定 **echo-on 场景**，且是否落档还取决于模型是否读回该区域。方向不变，证据强度须如实标注。
- **C6【加强·扫描未记的缓解】** PTY 命令按会话沙箱策略 confine，并继承「有 PTY 活动即拒绝放宽沙箱模式」的既有栅栏 ⇒ 「绕过沙箱」只对「另起第二个 PTY owner／移植」成立。同时须记：`packages/terminal/*` 对批准**零命中**（批准只在另一侧），故冻结记录「有审批、有日志」对 PTY **不准确**——**PTY 今天只有日志，没有审批**。
- **C7【更正·小项】** 归属检查的实际行号、后端第二道排他检查的更长消息、工具取 owner 的实际调用点，以及「结论第 9 条」应改写为**行号**以免与文档内编号混淆。

## 三、分歧清单（不抹平）

| 编号 | 分歧 | 各方主张 |
| --- | --- | --- |
| G1 | 需求是否已证 | 产品要先观测只读面板使用（C1 之后这才**可**观测）；架构认为层次问题不依赖需求量级；业务分析认为两个子议题都还没有威胁模型文档，观测替代不了它 |
| G2 | 写权限落点 | 产品倾向 per-install 显式开关；架构反对把安全不变量做成配置，主张「组合即授权」（preset 行 + entry-local realm）；业务分析指出客户端渲染门按仓库规则不是强制层 |
| G3 | 活动 send 处置 | 架构主张保留抛错语义、只在快照暴露「有无活动 send」、不仲裁不改语义；产品要「人随时能插话」——**两者不兼容**；业务分析指出仲裁会动既有契约，需**新决策**而非新配置 |
| G4 | 收口是否足够 | 产品与架构认为「内容通道唯一」已足够；业务分析认为不足，行为人归属无任何事件 |
| G5 | 密钥留档归属 | 架构归 S1；业务分析归 S2（记录义务）；产品视为「要用就接受」的产品成本 |
| G6 | 是否重开 2b | 产品主张不重开、写权限独立关闭；架构主张把作用域与 realm 结论并入 2b 重开；业务分析主张威胁模型补齐前不重开 |

## 五、本议题如何收口（照录）

**独立落成两个决策，且两个都要改判词**：S1 = 写入口不落在本期，但把「归属落点 = agent 作用域/lookup」与「写入口必须同 realm 组合」先写成**不可配置的安全不变量**并关闭实施；S2 = 结论成立但范围收窄到**内容通道**，并另立一条待办「行为人归属在日志中无位置」。

**不并入 2b 重开**：其原始措辞已被 C1 推翻，重开会把新事实塞进一份基于旧前提的决策记录。**也不整体关闭**：署名与归属两条必须在 2b 被再次提出前有答案。
