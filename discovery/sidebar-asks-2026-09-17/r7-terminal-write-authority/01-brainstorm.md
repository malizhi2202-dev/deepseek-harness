# R7-1 ① 头脑风暴：真终端的写入形态

本项源自第四项议题「真终端的写入形态」，即早先从终端议题切出去的 **2b**。**step-0 的一格事实推翻了本项的前提**：`ctx.terminals` 今天**已经有写入口**，所以「设计写入形态」没有据可查的子议题——它已经被设计完了。据此本项按门内指示拆成两个子议题，并把「写入形态」本身判为已溶解。

组织方式：两个子议题各由一个只读子代理做事实扫描与发散（本仓根下无 BMAD 辅助脚本，故退到三视角并声明偏离）。**全部结论只读取得，本项至今未改任何代码。**

## 一、子议题

| 编号 | 子议题 | 为什么有据可查 |
| --- | --- | --- |
| S1 | 浏览器侧终端 RPC 的**写权限信任与归属** | 落在既有「owner 映射不可配置」不变量的延长线上，且有两条现成先例 |
| S2 | 浏览器一旦能写，「**模型可见 ⟺ 已记录**」是否仍成立 | 直接触及仓库铁律，且被冻结的既有裁定第 9 行的前提会被写权限推翻 |

## 二、step-0：写形态已经存在（本项前提被推翻）

- 写入口是 `startSend(owner: Agent, id, request)`，自述「Start one exclusive interactive send」。
- **排他性是抛错而非排队**：`record.active !== undefined` 即以 `SEND_ACTIVE` 抛出；后端层有第二道同义检查。
- 写请求是**行导向**且非裸字节流：`TerminalSendRequest` 只有文本、是否补回车序列、取消信号；`TerminalSendOperation` 暴露结算、增量读取与请求中断，其中**中断语义被固定为 SIGINT**。
- 读面是**有界回溯分页**；`TerminalSendResult` 自带等待原因、会话状态与截断标志。
- 缝下面 `write` 是异步 provider 契约（注释自述「node-pty writes synchronously; the seam returns a promise for remote transports.」）；**`resize` 跨三层零命中**，只有初始行列。
- 结算词汇只有四种等待原因，**没有「被抢占／被取消」**。

⇒ 「真终端的写入形态」**已溶解**；真正缺的只有 `resize` 与「浏览器侧的权威」。

## 三、S1 的承重事实

| # | 事实 |
| --- | --- |
| F1 | `ctx.terminals` 每个方法都以 `owner: Agent` 起手；列表也只按该 owner 过滤 |
| F2 | 归属判定是**引用相等**：`if (record.owner !== owner) throw new TerminalError(… belongs to another agent, 'FOREIGN_SESSION')` ⇒ 伪造同 id 的另一对象会被拒 |
| F3 | 服务自述拥有 ids、publication、**authorization**、awaited cleanup ⇒ 授权属该服务，不属后端 |
| F4 | 模型侧工具从**执行 Agent** 取 owner，其 JSON schema 里**没有** owner 参数 ⇒ 「绝不接受客户端自报 owner」已是模型侧既有纪律 |
| F5 | **RPC 层不做任何调用者身份或权限判定**（逐字「The Gateway does not handle per-method permissions, caller identity, idempotency, or long-lived connection state.」；同处「every trusted host can invoke a mounted Remote endpoint」）；装饰器只有端点名/模式/作用域 |
| F6 | 归属解析的**既有强制点**：端点声明在 agent 作用域内，由生成描述符 + 网关 lookup 解析；wire 字段名是 `agentId` 而类型是会话标识；成品先例以 `@Remote async read(agent: Agent, …)` 形式存在 |
| F7 | 既有「绑定 owner 的安全判定」先例：有 PTY 活动时**拒绝放宽沙箱模式**，判据正是 `hasOwnerActivity(owner)` |
| F8 | 传输面**存在** WebSocket 复用路由，且升级走与 fetch **同一**信任闸；该面是既有实现 |
| F9 | 客户端信任面自述「**不是鉴权层**」；其上另有按 authority 绑定的浏览器认证 |
| F10 | 客户端能读「页面是否来自回环」，且已有「非回环就不装配特权 UI」的**先例**；但该标志的语义把「非浏览器上下文」也算作特权可达 ⇒ **纯客户端门控不是强制层** |
| F11 | Web-app 的补丁文件**不挂**终端行；但 Web 的 agent 平面由**每会话 agent preset** 拥有，而可选中（roster 第 3 位）的 `minimal` preset 已组合 `pty` + `terminal-bash` + pwsh 孪生 + 模型侧持久 shell 工具，并经 `agent-presets` 行与设置页暴露 |
| F12 | 客户端已有终端**呈现**原语（供工具卡片用），但**没有任何终端 RPC 消费方或终端面板包** ⇒ 只读面板 2a 尚未在代码中存在 |
| F13 | 仓库规则逐字「Protocol constants, external specs, and **security invariants stay fixed**.」 |
| F14 | PTY 命令按会话沙箱策略 confine；且 `packages/terminal/*` 对批准**零命中** ⇒ **PTY 今天只有日志，没有审批** |
| F15 | 写入口的授权若做成开关，其粒度只能是「该 preset 是否组合该行」；同层注释逐字「preset 即组合」且「与 shell 访问同等信任」 |

## 四、S2 的承重事实

| # | 事实 |
| --- | --- |
| G1 | 铁律三处措辞：LLM 包（「anything that reaches a provider request is reconstructable from the session log」）、根 `AGENTS.md`（「a **new** model-visible input requires a session event」）、架构文档（「**Model-visible means logged.**」） |
| G2 | 实际校验在不变量里：请求须冻结、带活 session、日志里须有对应步骤与请求头事件、消息须 JSON 等于日志派生、调用配置须等于折叠出的请求头 |
| G3 | 该不变量**只对**被进程内标记的 loop 请求生效 ⇒ 标题、压缩摘要等**旁路调用不受检** |
| G4 | 它**不覆盖** HTTP 头与 body 扩展字段，而后者**确实**进 provider 请求（有逐字自证） |
| G5 | 与不变量无关的一条独立事实：**旁路的既有范式是自落 log-only 事件**（标题调用派发前落事件；压缩以成对事件夹住调用）⇒ 从 G3 推出「旁路无需事件」是错推论 |
| G6 | 工具结果**就是**事件：内容生成、渲染、截断全部发生在落盘**之前**；请求由唯一投影规则从该事件逐字派生 |
| G7 | 终端整条链**不产生任何** session 事件；事件词汇表是生成物 + 闭集 + 读侧硬门 |
| G8 | 仓库存在合法的 **log-only** 事件（审计与权限预设类）⇒ 铁律是**单向**的，右到左不是义务 |
| G9 | 模型侧终端输出**今天已经在日志里**（经通用工具结果事件，无任何终端专属事件） |
| G10 | PTY **回显**存在（写入的字节会回显）；但「人类键入会回显」取决于行规程与读入程序，DSH 无法保证 |
| G11 | 被冻结的既有裁定第 9 行：用户自己敲的输出默认不进模型请求 ⇒ 按字面不必入日志；终端 UI 状态不入日志；若将来要可回放，另加一条有界、已清洗的可忽略事件，**绝不落字节级 transcript** |

## 五、方向清单（按层压缩）

- **`[文档]`**：把不变量**判定面的边界**写进铁律三处措辞旁（覆盖消息与调用配置、不覆盖旁路调用与请求头/扩展字段、对「内容取自未记录状态」结构性失明）· 把「终端内容进模型的唯一通道是工具结果、终端状态本身不可由日志重建」写进终端工具的既有局限清单 · 修订被冻结裁定第 9 行的**前提句**并保留其禁止字节级 transcript 的后半句 · 记录一条明确否定判据：**不要把终端状态本身变成事件** · 明确铁律**单向** · 写权限的显式风险记录（签字人/触发条件/后果/falsifier）。
- **`[Config]`**：**门内裁定后本期无此项**——授权由 preset 组合表达，不设 per-install 开关（原方向作废，留痕）。
- **`[宿主]`**：写入口必须复用既有 owner 解析（wire 只携带会话身份、结构上无法表达 owner）· 写入口必须与 PTY 注册表**同 realm** 作为 preset 行组合 · 定义人类写与模型写的互斥/抢占语义（门内裁定为**抢占**）· 浏览器写需与模型写对等的取消/超时链 · 后端可写性应是可校验的显式事实，在装配点失败而非运行时静默降级 · 若允许写，定义非回环/多用户下的默认行为。
- **`[客户端]`**：只读与可写必须是**两个不同的 UI 状态**，可写状态在非回环、未组合、后端不可写时不装配 · 客户端只发送会话身份与载荷，不得缓存、推断或回传 owner · 写入前给出可见提示「该会话内容可能被模型读取」· 不本地留存键入历史 · 不本地回显，显示内容以服务端分页为唯一权威 · 写操作携带可关联的操作标识。
- **`[静态门]`**：为「wire 不接受 owner」加可执行断言并证明写方法经执行器被拒 · 任何终端相关请求 DTO 不得含身份字段 · 若出现可写终端行或写端点被挂载，必须同时存在对应的组合声明 · 若采纳抢占，被抢占的结算落点必须可区分（涉模型可见文本，须同步 README 与快照）· 若最终加归属事件，必须走词汇表生成/校验流程并同步 SDK 期望输出与快照。
- **`[仅诊断]`**：把「浏览器写被拒绝」的原因分类记录（未组合/非回环/非 owner/写槽被占/后端只读）· 记录人类写与模型写在排他槽上的争用观测 · **在不变量旁留下「工具结果取自未记录的世界状态不构成 desync」的说明**，否则后来者会把它误判成漏洞并试图「修」成新增事件 · 把「人类写入使模型后续读取的增量归属不可辨」登记为**可观测性缺口**而非不变量缺口。

## 六、反例（对主要主张各 ≥2 条）

- **「服务端解析 owner 足以承载写权限」**：同一 Agent 的同一 PTY 被两个浏览器标签页持有时，两者都能合法通过解析，正确性完全依赖排他槽，而该槽今天返回的是**不可区分**的错误 ⇒ 用户看到「随机失败」；当信任地址被显式配置、页面从非回环载入时，解析仍正确，但「谁能到达该端点」已从「本机操作者」扩大为「任何能到达该 authority 的持凭据方」——该层自述不做 per-method 授权。
- **「既有信任/认证闸足以覆盖写权限」**：该闸的设计目标是反 DNS rebinding 与跨站读取、且自述不是鉴权层，它对读与写给出**完全相同**的判定，无法表达「读可、写不可」；浏览器认证按 authority 绑定 ⇒ 把「部署在何 authority」当作写授权的隐含前提，会在 authority 变化时**静默改变授权范围**而不是失败。
- **「写可以复用模型的 send 通道」**：中断语义被硬编码为 SIGINT，而浏览器真正需要「打断我这一条」与「结束整个会话」两种；模型侧 send 会等待就绪并产出四种等待原因，其判据来自提示符标记、前台进程组与静默阈值，逐键输入若走同一入口会让每次击键触发一次就绪轮询，**语义与成本都错位**。
- **「纯客户端门控即可」**：门控只影响「这个页面画不画按钮」，判定发生在浏览器进程里，任何非本仓库前端都不受约束；且该标志把「非浏览器上下文」也算特权可达 ⇒ 无法覆盖 SDK/自动化客户端。
- **「写权限不需要新事件」（S2 的主张）**：一旦决定把浏览器写的结果送进模型请求，按铁律第二分句即**必须**新增事件；今天模型侧输出经通用工具事件入日志 ⇒ 若浏览器写的输出也走该通道却没有任何事件标注「来源是人而非模型」，**重放会把人的输入误读为模型行为**。
- **「只读的安全结论可直接外推到写」**：只读的残余风险被限定为「同机其他本地用户」且开关可选，写把影响从信息泄露升级为任意命令执行，可选/必需的前提随之改变；只读的暴力面是「读到多少行」，写路径还多了「能否构造转义序列、能否触发终端协议回复」，而该回写通道与浏览器写的交互是只读从未面对的新面。
- **「抢占是既有能力」**：结算词汇里没有「被抢占」这一取值 ⇒ 被抢占的模型 send 只会以四种之一结算，**模型看到的是一个没有原因的中断**。

## 七、交给 ③ 的未决问题

浏览器写的**归属单位**（会话 / PTY 会话 / 当前持有写槽的连接）· 排他槽是正确模型还是待替换模型 · 浏览器写的结果是否应进入模型上下文（选「是」即触发铁律第二分句）· 写权限是否连带重开 2b · 开关粒度与默认值 · 是否需要 `resize`（引入等于新增一条跨缝方法，属独立决策）· 客户端展示原语的复用与新建 · 被拒绝原因是否应作为可观测事实暴露给遥测。
