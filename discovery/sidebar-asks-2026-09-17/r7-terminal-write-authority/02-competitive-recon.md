# R7-2 ② 竞品／技术侦察：真终端的写入形态

**本步的真实产出是一份「无外部材料」的诚实记录，外加一份仓库内可比先例的对照表。** 本环境检索能力不可用，两个子议题的只读侦察与 ④ 的三视角评审**均声明未取得任何承重的外部资料**。因此本步**不承担**任何结论，也不得被后续阅读者当作外部验证。

## 一、外部材料状况

| 项 | 状况 |
| --- | --- |
| 检索能力 | 不可用 |
| 成功抓取的外部一手源 | **1 条**，且仅作方向性参考（某终端共享工具把「可写」做成显式开关、默认只读，并把来源校验与凭据各自独立成选项） |

## 二、仓库内可比先例（这才是本步可承重的部分）

由于外部材料缺失，本步以**仓库自身的既有先例**为对照面。下列对照均在 ① 中已核实。

| 待决问题 | 既有先例 | 与本项的关系 |
| --- | --- | --- |
| 浏览器请求如何获得 Agent 权威 | 已有成品端点以 `@Remote async read(agent: Agent, …)` 形式存在，wire 只携带会话身份，由生成描述符 + 网关 lookup 解析 | 直接可用，无需新建机制 |
| 安全判定如何绑定 owner | 「有 PTY 活动即拒绝放宽沙箱模式」，判据是 `hasOwnerActivity(owner)` | 写权限的判据应与之同构 |
| 外部可变状态如何进入模型视野 | 有插件每轮拉取外部会话状态作为预备步骤消息，且**必须先落成事件**（落盘点在 agent-loop 侧） | 若将来要把人类输入送进模型请求，须照此落事件 |
| log-only 事件是否合法 | 审计类与权限预设类事件都是 log-only、不入模型转写 | 铁律因此是**单向**的；归属事件不违规 |
| 特权 UI 如何收窄 | 客户端已有「非回环就不装配特权 UI」的先例 | 只能作**呈现**，不能作强制层（其标志把非浏览器上下文也算特权可达） |
| 授权如何表达 | 同层注释逐字「preset 即组合」且「与 shell 访问同等信任」 | 门内裁定「组合即授权」的依据即此 |

## 三、由此确认的三条（与 ④ 的更正互相印证）

1. **不需要新建权威机制**：归属落点已有强制点，写权限的唯一正确落点就是复用它。
2. **不需要新建「组合」概念**：preset 已经是组合单位，授权可直接由它表达。
3. **需要新建的东西只有两样**：跨缝的 `resize`，以及抢占后的**可区分结算**（见 `03-conclusion.md` 第二节的必答项）。

## 四、本步的局限（必须与结论一起读）

- 无外部对照 ⇒ **无法回答「别的实现是否也这样做」**，因此本项的一切建议只能以仓库内一致性与既有条款为依据。
- 唯一外部数据点与门内裁定方向相反且未自核 ⇒ 它在记录中**不构成反证**，也不构成支持。
- 三视角评审同样无外部材料 ⇒ **不存在独立于本仓库的第二意见来源**，这是本项最实质的证据缺口。
