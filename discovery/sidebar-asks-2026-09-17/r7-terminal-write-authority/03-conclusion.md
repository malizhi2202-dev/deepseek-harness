# R7-3 ③ 结论与建议：真终端的写入形态

**一句话结论：本项两分。S1（浏览器侧写权限的信任与归属）判为「写入口不在本期」，但把它赖以成立的两条**不可配置的安全不变量**先写下来并关闭实施；S2（「模型可见 ⟺ 已记录」是否仍成立）判为「内容通道未被破坏，但断言必须改成两分式」。**

本项由第四项议题「真终端的写入形态」拆出，两个子议题都按门内裁定重新改过判词（见 `05-review-record.md`）。

## 一、S2：铁律未被触发，但断言必须两分

**判定链**：终端字节进入模型的通道**只有**工具结果这一条；而工具结果**就是** session 事件——内容的生成、渲染、截断全部发生在 `session.append('tool/result', …)` **之前**，请求再由 `session.deriveMessages()` 从该事件逐字派生。因此「模型看见的终端字节」与「日志里的终端字节」本就是同一批。浏览器获得写权限改变的是**谁**产生内容，不是**内容走哪条通道**。

**⇒ 字面无需新增任何 session 事件，也无需落字节级 transcript。**

**但铁律的措辞宽于实际校验面，这条边界必须写进记录否则会被误用**：

- `packages/core/agent-loop/src/invariant.ts:22` 只对携带 `markAgentLoopRequest` 进程内身份的请求生效 ⇒ 会话标题、压缩摘要等**旁路 LLM 调用完全不受该校验**。**注意不能由此推出「旁路无需事件」**：仓库的既有范式是旁路**自落 log-only 事件**（标题调用在派发前落 `session/title-llm-request`；压缩以 `compaction/start`·`end` 夹住调用）。
- `invariant.ts:44-49` 的比较面是 `model`/`system`/`temperature`/`maxTokens`/`stop`/`tools` **加** `:39-42` 的完整 `messages`；**HTTP 头与 `dsh_*` body 扩展字段确实进入 provider 请求，却在这个面之外**（该事实由 `docs/deepseek-llm-api-wire-extensions.md:7` 逐字自证）。
- 比较的两侧常是**同一个冻结对象**（`packages/core/session/src/surface.ts:79-116` 是唯一投影规则），因此它对「这段内容取自未记录的终端状态」**结构性失明**——与第三项议题中「不变量只证明 loop 写的等于 loop 发的、证明不了执行的等于描述的」是同一根源。

**⇒ 采纳两分式断言**（门内裁定）：

1. **内容面**：终端内容进模型只有工具结果这一条通道 ⇒ 铁律要求的事项已由既有事件满足，**无需新事件**。
2. **归属面**：**行为人的归属在日志中没有任何位置** ⇒ 另立一条待办，不得被第 1 条吸收。

**同时记录的副作用（真实风险，非铁律违反）**：PTY 回显使人类在提示符处键入的**可见内容**可能进入 scrollback，之后经 `terminal_read` 逐字进入 provider 请求并**永久留在 `tool/result`**——这正是被冻结的既有裁定自己列为禁止的「提示符处输入的密钥」形态。**证据强度须如实标注**：写入 PTY 的字节会回显有注释自证，但「人类键入会回显」取决于行规程与读入程序（关闭回显的读入程序是现成反例），故本风险限定为 **echo-on 场景**，且是否落档还取决于模型是否读回该区域。

## 二、S1：写入口不在本期，但两条安全不变量先立

**写权限不可能由 RPC 层声明或拦截**：该层逐字「The Gateway does not handle per-method permissions, caller identity, idempotency, or long-lived connection state.」，同处逐字「every trusted host can invoke a mounted Remote endpoint」；装饰器只有端点名、模式与作用域三个维度。

**⇒ 两条不可配置的安全不变量（本期只立条款、不开实施）**：

1. **归属落点已存在，必须复用**：浏览器请求只携带**会话身份**，端点声明在既有 `agent` 作用域内，由生成描述符 + 网关 lookup 解析出 live Agent。**wire 结构上无法表达 owner**，故「绝不接受客户端自报 owner」不是纪律而是既有强制点（成品先例 `@Remote async read(agent: Agent, …)`，其自述为「target Agent resolved from the Session identity on the wire」）。按仓库规则「安全不变量不可配置」，这一点不得做成任何字段。
2. **组合即授权（门内裁定）**：写入口的授权由「**该 preset 是否组合该行**」表达，且必须与 PTY 注册表**同 realm**。依据是该层自己的注释——「preset 即组合」且「与 shell 访问同等信任」。**因此不设 per-install 开关**，客户端门控退为**纯呈现**、永不作为强制层；原先按部署开关写的条件连同其 per-install 框架一并改记。

### 抢占（门内裁定，与专家团建议相反）

门内裁定「**人随时能插话**」，并在「允许抢占活动 send」与「新增非排他写入路径」之间选了**前者**。必须同时记录三件事：

- **「打断」的一半今天已经存在**：`signal(owner, id, signal)` 只有一行实现、**没有 `active` 守卫**，而活动槽只挡 `startSend` ⇒ 人类今天就能随时打断模型正在跑的命令。真正缺的是「**喂字**」。
- **抢占改的是既有契约**：`TerminalSendOperation` 的 `cancel()` 语义与 `SEND_ACTIVE` 的硬拒绝都要动，这是**新决策**而非新配置；不得把它描述成既有能力。
- **实施前必答（已核实的硬缺口）**：结算词汇里**没有**「被抢占/被取消」这一取值（只有 `stdin_read`／`inferred_idle`／`timeout`／`session_exit`）。因此被抢占的模型 send 会以四者之一结算，**模型看到的是一个没有原因的中断**——这与第三项议题发现的「结果入日志、成因无法表达」是同一模式，而此处更重，因为模型会据此行动。⇒ 若采纳抢占，必须给被抢占的结算一个**可区分的落点**（该字段随工具结果入日志，属模型可见文本，故需同步 README 与快照），**或**在记录里明写「模型只会看到一次无原因的空闲」。

## 三、五条缺口的处置（门内裁定：按建议分配）

**本期落盘**：冻结记录的两处事实更正与其前置条件状态改记；写权限的显式风险记录（签字人、触发条件、后果、falsifier）。

**挂为「2b 再被提出前必须有的答案」**：威胁模型文档（机器上其他本地用户、页面来源、trusted-host 面）· 署名（谁接受「无审批、无事件、命令在会话沙箱策略内执行」这一组合——注意 **PTY 今天本就没有审批**，只有日志）· 抢占的详细语义（见上）· **2a 在代码里尚不存在**（客户端侧没有任何终端包），故「先验证有人用只读面板」这句目前**没有可观测对象**。

## 四、两处对冻结记录的更正（本期落盘）

1. **传输面存在 WebSocket**：`'/api/remote.mux'`「Exact WebSocket route carrying every Typert Remote stream」，宿主侧持有 `noServer` 的升级服务，且升级走与 fetch 同一信任闸。⇒ 冻结记录「传输面……没有 websocket」为假，其「输入／输出／尺寸／重连都要自建分帧」过宽：**输出推送与重连已由该面拥有**，真正缺的只有**输入**（写是行导向而非逐键）与 **resize**（跨三层零命中，只有初始行列）。
2. **PTY 已随可选中 preset 进入 Web 会话**：「Web 面不挂终端行」只对 web-app 的补丁文件成立。Web 的 agent 平面由**每会话 agent preset** 拥有，而可选中（roster 第 3 位）的 `minimal` preset 已组合 `pty` + `terminal-bash` + pwsh 孪生 + 模型侧持久 shell 工具，并经 web-app 的 `agent-presets` 行与设置页暴露。⇒ 六条前置条件中「目标 preset 确实挂了 PTY 行」**已经满足**；2b 的真实含义不是「挂 PTY」，而是「**把既有 owner 会话暴露给浏览器**」。

## 五、安全面上未记账的缓解（须随更正一并记入）

PTY 命令按会话沙箱策略 confine，并继承「有 PTY 活动即拒绝放宽沙箱模式」的既有栅栏 ⇒ 冻结记录里「绕过沙箱」只对「另起第二个 PTY owner／移植」成立。但 `packages/terminal/*` 对审批**零命中** ⇒ 冻结记录里「有审批、有日志」对 PTY **不准确**：PTY 今天只有日志，没有审批。
