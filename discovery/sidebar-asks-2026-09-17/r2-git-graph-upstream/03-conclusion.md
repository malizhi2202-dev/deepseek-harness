# R2-5 ③ 结论与建议

**结论：不是"修插件"，而是"对齐版本线"。**

1. 上游没停更，反而跑在前面（git-graph 调查前一天发版；0.19.x 已改为消费核心右栏包）⇒ 决策 2「先查上游是否已修 API」的答案是：**上游已修，但修到了比当前检出的树更新的线上**。
2. 三条路：
   - **A（推荐，待 P2 决策）**：把检出推到上游支持的点（如 `0.1.5-rc.1`）后启用上游最新版；同时兑现 Git 图 + 文件工作台 + 真 xterm 终端（正是负责人最初点名的三项）。代价：升级 DSH 本身；须先在有界范围内评估迁移成本。
   - **B**：留在 `0.1.3-alpha.2`，核心自建最小只读 Git 视图 —— 但 F29 表明核心**没有 git 接缝**，自建＝新造 Service Definition / Provider / Consumer 三角，且会与上游形成第二个呈现层 owner；若走此路必须显式标注"**有期限的临时物**"（架构师条件）。
   - **C（否决）**：硬配中间版本（映射表显示不存在覆盖 `0.1.3-*` 的版本）。
3. 事实 C5 修正：该 profile 内 `disabled` 插件的真正成因是**版本线错位**，不是"插件烂"。

**待定**：P2 版本线决策（本轮未决，作为开放分支保留）；决策当日需复核版本映射表（分析师条件）。
