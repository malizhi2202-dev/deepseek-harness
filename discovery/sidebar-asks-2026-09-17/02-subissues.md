# 子议题 S1–S6：五步流记录与结论

## S1 任务观测的形态与信息架构

**子议题**：任务观测是一个面板还是几个？后台任务的观测深度到哪一层？与会话头部已有入口如何分工？

**① 头脑风暴**（40+ 想法收敛为 15 个方向，Top 5）
1. **边界合约**（只读事实与语义归核心；有副作用的操作归生态）—— 它是其余所有方向的前置裁决。
2. **三类级联显式命名**：结构级联（父→子派生，可证）、时序级联（同轮次调用顺序，可证）、失败级联（启发式，必须标注为推断）。
3. **世系骨架 + 节点注解** —— 唯一能被证明存在的结构就是世系树。
4. **主从双栏**（一个 kind + 一个详情区，而不是并列多个 tab）。
5. **证据锚点与"可证/推断"分级** —— 每条结论可跳到 trajectory 事件 seq。

创意补充（负责人未提）：一条时间轴代替三块列表、失败指纹聚合 + 错误源五分法（模型/工具/宿主/网关/用户中断）、一键导出 Markdown/JSON 任务报告、join 只写一次（把"会话×子代理×job×错误"的联合派生放到对象层 selector）。

**② 竞品证据**：见 `04-competitive-evidence.md` Q2（GitHub Actions 只画 `needs` 声明的边；Langfuse 区分推断拓扑与声明拓扑；OTel/K8s 把"未知"当一等状态；Airflow 用同页 tab 而非新增面板）。

**③ 结论**
- 任务观测 V1（todos + jobs）**合理且已交付**；但 jobs 段与会话头部 `ui-jobs` 的入口重复（F16 相邻事实、`conversation.session.header.actions`），侧栏应只保留"汇总 + 失败"，实时输出与强杀留给头部与生态。
- 不做并列多 tab；列表/树/时间线作为**同一面板内的镜头**。
- 级联只画两类可证边，第三类默认不画并显式标注"无任务依赖模型"。

**④ 专家团**：PM 指出真正缺的是**从观测到动作的闭环**（点失败能重试/换模型/跳 seq/派修复子代理），只有展示事实就是仪表盘；商业视角要求验收口径（"任意一次失败 ≤2 次点击内看到它属于哪一类"）。

## S2 核心自研 vs 生态已装

**子议题**：终端、Git、文件、成本这些已装插件覆盖的需求，核心该自研还是委托生态？右侧栏扩展点的粒度够不够？

**① 头脑风暴**（15 个方向，Top 5）
1. **评估能力缝**（唯一生态零覆盖且是真语义缺口）—— 定义缝而非画面板。
2. **Git 事实资源地址化**（把"git 即为记忆"落成 `dsh-resource://` 地址语义）。
3. **补 icon/badge 与 rail/footer seat** —— 决定第三方 tab 能否被发现、能否表达状态。
4. **整列替换者 provider 缝** —— 不解决它，核心投入的 tab 类型可能落在不可见的表面上。
5. **生态优先判定门** —— 把"先查官方库"从一次口头指令变成可复算步骤。

**② 竞品证据**：见 `04-competitive-evidence.md` Q1（VS Code 要求每个 View 必须有图标、容器内 3–5 个为宜、二级侧栏是用户财产；JetBrains 默认只显示"几乎每个项目都要用的"；Cursor 论坛记录扩展面板无法停靠其保留给 agent 的二级侧栏）。

**③ 结论**
- 该子议题的原始论证（"生态已覆盖终端/Git/后台任务，故核心不必自研"）在当前启用集合内**不成立**（见 C2）：这些插件已安装但被禁用。
- 但结构性问题成立且值得修：tab 类型缺 icon/badge/order（F1）、"+"是 guide-only 且芯片溢出无菜单（F3）、无 provider 缝。
- 判定顺序固定为：**先查插件库与已装/已禁用状态 → 判定覆盖度 → 只有空白才自研**，并把"已安装 ≠ 已启用"写进检查项。

**④ 专家团分歧（未收敛，留待实现前裁决）**
- **PM vs 架构师**：先出面板价值，还是先合元数据？架构师的技术理由成立 —— 没有 `order` 字段，"默认可见预算"无法表达；kind 一旦进入布局记录再补 `order` 属破坏性迁移。负责人选择**元数据先行**。
- **架构师 vs 商业**：Git 走"移植已装但被掀翻的插件"还是"自建最小只读视图"？前者快但收维护债，后者可控但重造。负责人选择**先查上游是否已修**。

## S3 成本观察与评估观察的数据可得性

**子议题**：这两个面板的数据今天在不在？最小可用形态是什么？要不要新宿主能力？

**① 头脑风暴**（15 个方向，Top 5）
1. **零宿主改动双面板基线**（成本 = tokenUsage + sessionStats + contextPressure + TurnTokenUsage；评估 = 窗口内派生事实）。
2. **`sessionOutcomes` 派生投影**（唯一真缺口：全会话失败计数）。
3. **验证证据面板**（isError 计数、reason 分布、max-tokens、interrupted、产物文件数）。
4. **子代理树成本 roll-up**（用 `SessionListEntry.projectionValues.tokenUsage` + `parentSessionId`）。
5. **数字来源标签**（provider-reported / heuristic / 推断；并物理禁止把不可加项相加）。

**② 竞品证据**：见 `04-competitive-evidence.md` Q3（Claude Code 标 "estimate"；ccusage 内嵌价表 + 可覆盖 + `--no-cost`；LangSmith/Langfuse/Helicone 未命中价格即不推断、历史不回填；OTel 只标准化 token 不标准化钱）。

**③ 结论**
- **成本**：token/耗时/上下文占用口径**零宿主改动可行**；**金额口径不可行**（F18 无价源）。若做金额，必须"可编辑价表 + 未命中显示未定价 + 历史不回填"，且明确它**不是账单**（与 token-meter 既有定位一致）。
- **评估**：只展示派生事实，**不显示正确性、评分、通过率**（分母无定义）。**唯一宿主缺口是全会话失败计数**，补法为一个投影单元，无新会话事件、无格式版本变更（F20）。
- **扇出归属（架构师提出的开工前必答项）**：聚合放**宿主投影单元**（照 `session-stats` 模板新建 `packages/session/session-outcomes`，纯 fold + `wire.view`），不做客户端逐会话拉全日志；这样既零扇出又不动既有 schema。
- 补充信号源（负责人未提、但满足"派生事实"约束）：**人类反馈事件**（positive/negative）与**产物事实**（`ui-deliverables` 的"成功 mutation 调用 → 文件路径"先例）。

**④ 专家团**：商业视角当场否决"一键导出 Markdown/JSON"（新的数据外发面）与"人类反馈一等化"的隐私面；主张把改进项从 12 条砍到 ≤4 条并给"有用"的验收标准。负责人未反对该否决。

## S4 清单里"不属于右侧栏"的三项

**子议题**：其他模型（gpt5.6 / claude-code）、archiy、验证实例到主实例的验证流程，各归到哪里？

**① 头脑风暴**（15 个方向，Top 5）
1. **三分类归位法**（每条诉求加"归属"必填：右侧栏 tab / 设置页 / 流程文档 / 插件市场 / 非诉求）。
2. **其他模型归零化**（先验证后立项：先确认这些模型在现有 pi-ai 路由 + `/model` 下是否可用）。
3. **验证流程迁出并配方化**（写成 process 记录 + 第二端口预检配方）。
4. **archiy 三问澄清**（旁边是什么 / 是不是 archive/artifact/ArchiMate 之类笔误 / 想让它出现在哪、点了发生什么）。
5. **插件优先写进流程**（仓库已有 `find_dsh_plugin`，插件市场类 bundle 亦已存在）。

**② 竞品证据**：无直接竞品问题（属产品内部归属判定），依据为 DSH 自身 seam（模型选择已有 `ui-model-selection` 与 `/model`、`subagent-model-selection` 已启用）。

**③ 结论**
- **其他模型不属右栏**，属"供应商与模型接入"议题：真缺口只有"CLI 作为一等 LLM 路由"的 adapter（`claude-code` 今天只能是被委托的子代理，见 F23）；报错属网关侧（F22），改 DSH 或 pi 配置无效。
- **archiy 冻结**，未澄清前不进开发队列。
- **先在验证实例上验证、再切到主实例是一条流程纪律，不是需求**；且已被 C1 修正为"刷新即可"。另需修正：验证实例应脱离主实例进程树并独立 `DSH_HOME`（F25）。

**④ 专家团**：一致同意归位判定；商业视角附议冻结 archiy。

## S5 右侧栏的容量与导航

**子议题**：面板会越来越多，右栏怎么吸收增长？默认开哪些、怎么分组、与整栏第三方插件如何共存？

**① 头脑风暴**（15 个方向，Top 5）
1. **增长代价阶梯 + 地址域判据**（分区 < kind < pane < surface < 独立窗口；只有拥有独立 `dsh-resource://` 地址域的能力才配新增 kind）。
2. **分区词表**（tab 类型与 guide 条目增加 core 拥有的 `section` 字段，`order` 只在分区内生效）。
3. **声明式可见性 + 默认开启预算 + 门禁**（默认态显式声明；对重复 `order` 与超预算默认开启报错）。
4. **有界 chip 条 + 溢出**（只画 pinned + 最近使用的 N 个，其余进"更多"；N 走已验证的 Config 而非硬编码）。
5. **声明式表面所有者 + boot 冲突检测**（整栏插件必须声明"我拥有右侧栏表面"，两个所有者即响亮失败）。

**② 竞品证据**：见 `04-competitive-evidence.md` Q1（VS Code 3–5 上限与"View 必须有图标"、二级侧栏归用户；JetBrains 默认可见性规则；Airflow 用同页 tab）。

**③ 结论**
- 治理原则：**默认隐藏 + 溢出入口 + 数量预算**，而不是禁止新增类型。
- 因 F1（无 `order`/`icon` 字段），"默认可见预算"与"降到图标轨道"今天无法表达 ⇒ **元数据先行**是执行顺序上的硬前提（负责人已采纳）。
- 准入判据采纳：新增 kind 需拥有独立地址域。
- 与整栏第三方插件的关系：当前无需处理（`better-sidebar` 已禁用），但保留"声明式表面所有者 + 冲突检测"作为后续方向。

**④ 专家团**：架构师主张元数据先行（负责人采纳）；商业视角提醒每个新 kind 都是长期维护税，要求验收标准。

## S6 智能体派生面板

**子议题**（负责人后补）：展示代理之间的树状派生关系，命名"智能体派生面板"。

**① 头脑风暴**（12 项技法、约 75 个想法，15 个方向，Top 5）
1. **独立 `agents` kind 的新包，带自己的 guide 条目** —— 唯一能承载负责人命名与图标的表面。
2. **用 `byId` 全量会话摘要建"摘要森林"** —— 这才是它与头部 336×560 浮层不重复的原因：完整且可回溯、零宿主读取。
3. **把 jobs 挂到所属代理节点下**（`jobsBySession` 的键即归属，零宿主改动，浮层从未做过）。
4. **从真实属主导出 `flattenLineage`**（`@deepseek-ai/dsh-api-session-controller/client`），而不是第三次复制或违反客户端导出规则 3。
5. **运行路径自动展开 + 只看运行中过滤**。

创意补充（负责人未提）：派生历史（含已完成/失败代理，变成运行记录）、头部↔面板双向桥（浮层看一眼、面板留着看）、扇出护栏（并发后代数与树深告警）、**每节点时间轴微条**（在不伪造依赖边的前提下对"任务图谱"的唯一诚实回答）、单子链折叠（VS Code 的 compact folders）。

**② 调研**：未单独跑（本子议题的 ① 已含浮层与文件树的 file:line 先例；竞品中 agent 图视图部分见 `04` Q2：AutoGen Studio / CrewAI 未取证）。

**③ 结论**
- 形态：**独立 `agents` kind 的新包**（第四个 kind），不是"任务观测"内的镜头，也不是改名。
- 复用策略：**不复用组件（浮层的 props 绑在头部 slot 契约上）、不跨包运行时导入（`packages/client/AGENTS.md` 导出规则 3）、算法回到真实属主导出**。
- 头部浮层**保留**，并增加"在面板中打开"入口；侧栏默认折叠，头部是唯一的常驻信号。
- 数据来源：`useSessions(state => state.byId)` 建树（`subagentsByParent` 是懒的，见 F14），已加载的目录用于权威活性叠加，`summary.running` 作恒在回退。
- 节点内容：展开箭头、状态点**加状态词**（不靠颜色单独表意）、label、`title · mode · activity`、**子树 token/耗时 rollup**（浮层只有自身合计）、运行中后代数、附带 job 数。
- 行为：逐节点折叠（默认展开"含运行中节点的链 + 第一层"）、14px 逐级缩进（>5 层收敛为 `×N` 深度标记）、点击打开会话、诊断行为 `aria-disabled` 并带本地化原因、孤儿标为根而不丢弃、环渲染为已访问且不可再展开、`parentAvailable: false` 给显式提示行、加载态用摘要骨架行、错误态保留最后一次好树 + 重试、空态显式命名会话。
- 约束：一个**安全**深度上界（参照 `MAX_TOOL_CALL_TREE_DEPTH = 256`），不做 UX 截断与虚拟滚动；插件需把 `sessions` 加入 `inject`（为懒展开与导航）；用 `useTabInfo` 在 tab 不可见时停掉 1s ticker；全部文案走字典（`verify-client-ui-i18n` 拒绝硬编码），`zh` 为验收面。
- 明确否决：任务依赖图（无依赖模型，边是伪造的）、客户端跨会话翻会话日志做失败归因（需宿主聚合投影，改为三态 known-failed / unknown / ok）、只画活子代理（毁掉复盘用途）、力导向图画布（窄栏可读性差）。
- **可被反驳的承重论证**（子代理自报，建议实现前对抗性检验一次）：只有 tab 类型能拥有 guide 条目，故必须独立成 kind。若产品接受"智能体派生"只作为镜头标签、不需要可发现的名字，更便宜的可逆路径重新打开。

**④ 专家团**：未单独跑；负责人在第⑤步已就其位置作答（与任务观测同为默认可见，且采纳元数据先行）。
