# @deepseek-ai/dsh-client-ui-sidebar-automation

[English](README.md) | 中文

## 概述

`dsh-client-ui-sidebar-automation` 把 `automation` 注册为右侧栏的标签类型：一个可选页面，绘制[宿主端点](../../api/workspace-automation/README.zh.md)投影的工作区自动化台账——先是工作区定时器状态，然后是全部保留的运行，最新在前。每次运行按设计要求的顺序回答设计要求的四个问题：比较了什么、做了什么或为何没做、涉及哪些路径、接下来会怎样。

本面板按设计只读。自动化定时器由工作区注册表与自身配置自行武装，因此这里没有立即运行、暂停、恢复、重试或排期控件：一个不可能起作用的控件比它缺席更糟，设计把这些决定都留给编辑工作区的人，而不是这一页。唯一的控件是再次读取台账。

<a id="use-this-package"></a>
## 使用本包

打开右侧栏的引导页并选择 **自动化**，或从类型选择器打开 `automation`。该标签以工作区而非会话为键，因此面板先解析其会话所属的工作区，再读取该工作区的台账；不属于任何工作区的会话会如实说明，并且不向宿主索取任何东西。

该类型是 `available`，绝不是 `default-on`：多数会话从不运行定时器，而右侧栏的常驻席位属于回答会话问题的界面。其 `order` 为 800，排在 git 页之后，引导项位于序号 80。

<a id="understand-the-implementation"></a>
## 理解实现

文件切分即分层：类型是什么（`definition.ts`）、它保留什么（`store.ts`）、它如何读取宿主（`face.ts`）、一个结果如何成为一句话（`lines.ts`）、它绘制什么（`AutomationBody.tsx`）、它说什么（`locales.ts`），以及只负责把它们接起来的 `index.ts`。

store 每个标签保留一个桶：读取进行中、它落定的失败，或它落定的台账。每次运行的四个回答都在绘制时从台账推导而非存储，投影因此始终是决定一次运行结果含义的唯一之处。

face 按标签给出的工作区 id 读取 `remote.workspace.automationLedger`，并把答案交给 store。每次读取都带上该标签自己的 signal 与一个世代计数，因此后发的一次重新读取不会被更早的读取覆盖，而关闭的标签会中止其读取并丢弃它的桶。

`lines.ts` 是设计的可解释性要求所在：每个结果变体一个函数、每个下一步一个函数、读取被拒一个函数，各自按其判别式穷尽 switch，台账新增一个原因会在这里编译失败，而不会绘制成一张空卡片。

这里什么都不写：面板完全没有改动路径，它唯一的 Remote 调用就是这次读取。

<a id="model-experience"></a>
## Model Experience

### 自动化面板

#### What the model sees

没有直接影响。该标签不注册工具、提示词段落或会话事件，它唯一的宿主调用是 `remote.workspace.automationLedger(workspaceId)`，一次答案只在浏览器里绘制的读取；面板展示给人的内容只经由各次运行自己写进仓库的提交消息触达模型，而那是仓库内容。面板从不组装请求，也从不向会话添加消息。

#### Token effect

没有。打开标签、读取台账、重新读取都不给任何请求增加 token，这里也没有任何东西塑形提示词。

#### KV Cache effect

无直接失效；本包不组装、不塑形任何模型请求。

## Known Limitations and Deferred Work

- **只读是刻意的。** 没有立即运行、暂停、重试或排期控件：定时器由工作区注册表与自身配置武装，因此这一页只能展示台账已经记录的内容。想要不同排期的读者改的是工作区，而不是面板。
- **台账缺的事实，面板无法补正。** 比较行按该字段自己的名字绘制台账的 `observedUpstreamOid`，而宿主 README 已记录：该值是对齐任务观察到的本地 head，而非上游尖端。修正这个读法需要 git 缝隙提供上游提交 id；在这里编造一个，就是设计禁止的重算。
- **没有台账的工作区读作 unrecorded。** 那是从未跑过定时器的工作区的正常状态，面板用一行绘制它而非当作失败，因为两者是不同的两件事。
- **两个界限都属于端点。** 到达多少条运行、多少条路径是宿主读取的配置；面板只报告界限藏起了什么，想要更多的读者改的是 `cordis.yml` 而不是面板。
- **没有跨工作区视图。** 一个标签绘制一个工作区，与台账自身的键一致；没有把各工作区定时器汇总起来的页面。
- **读取被拒时整页替换。** 载体或未分类的宿主失败会用其消息与重新读取控件替换面板，而不是把陈旧台账留在屏幕上；这里没有部分读取，也没有重试循环。
- **工作区是从客户端工作区模型拼接的。** 台账不携带路径或标题，因此标题栏的名称与路径来自工作区 hook；某个会话的工作区在本浏览器未注册时，即使宿主有它的台账，也会绘制 no-workspace 状态。
- **按当前台账的词汇表构建。** 本波之后台账新增的运行结果或下一步会先在宿主包的穷尽检查处编译失败，因此两半一起移动，而不是其中一半绘制一张没有解释的卡片。

### 开发备注

<details>
<summary>维护者的工作上下文——点击展开</summary>

未发布运行时不变量 companion：面板不持有任何跨插件关系，它所依赖的规则——每标签一个桶、每工作区一次读取、以及落定结果不会被更早的读取覆盖——由 `packages/client/ui-sidebar-automation/src/client/` 中的 store 与 face 强制。

测试套件在真实的 store 实例、脚本化 Remote 与脚本化工作区 hook 之上挂载面板主体，断言读者看到的内容：读取可能落定的每种状态、每种结果变体（包括什么都没做的那些）按设计顺序给出的四个问题、路径及其装不下的计数，以及一次真的再次询问宿主的重新读取。标签类型也会对照右侧栏发布的槽位声明契约断言。
