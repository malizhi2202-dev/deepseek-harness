# @deepseek-ai/dsh-client-ui-sidebar-sources

[English](README.md) | 中文

## 概述

`dsh-client-ui-sidebar-sources` 把 `sources` 注册为右侧边栏标签页类型：一个 available 页面，列出宿主资源注册表服务的每个远程资源实例，附带其提供方报告的状态、其配置点名的凭据引用、由该类型自身配置 schema 构建的设置表单，以及该类型强制执行的硬限制。它是远程资源库的浏览器半边——宿主半边是资源缝隙之上的 `dsh-api-sources`——自身不持有任何源知识：有哪些类型、每个类型能回答什么、哪些字段配置它，全部来自宿主。

它文案中的两行是面板的诚实而非装饰。凭据只以引用名出现：面板既不读取也不展示密钥值，表单只在读者亲自输入时才写入一个值。未配置的源被画作未配置、且没有自己的连接控件，因为设计从「是否已配置」推导源是否连接，而不是从某个开关。

<a id="use-this-package"></a>
## 使用本包

打开右侧边栏的引导页并选择 **远程资源**，或从类型选择器打开 `sources`。面板在挂载时读取宿主的源列表，并为每个实例画一张卡片：其状态、有则显示其最近错误、其提供方声明它能回答什么、按引用名显示的凭据、其 schema 声明的设置表单，以及其类型强制执行的硬限制。**测试** 探测一个实例且不改变任何东西，**重新加载** 重读列表，**保存**/**丢弃** 暂存与放弃编辑。

该类型是 `available`，从不 default-on：配置远程资源是人主动要求的事，而右侧边栏的常驻席位属于回答会话问题的界面。其 `order` 为 700，排在渠道页之后，其引导条目位于 order 70。

源的配置属于宿主的设置文档，写入它的一切后果由宿主拥有：字段落在哪一层、revision 栅栏，以及该写入是否被存储。面板发送暂存的操作，然后读回宿主实际存储的内容。

<a id="understand-the-implementation"></a>
## 理解实现

文件划分即分层：该类型是什么（`definition.ts`）、它保存什么（`store.ts`）、它如何驱动宿主（`face.ts`）、它画什么（`SourcesBody.tsx`）、schema 如何变成表单（`form.ts`）、它说什么（`locales.ts`），以及只把它们接起来的 `index.ts`。

store 保存每个标签页的源列表、每个实例的设置描述、读者暂存的草稿，以及忙碌与失败标志。其记录以实例的不透明 `key` 为键，而不是以类型为键，因为一个类型可以声明多个实例。实例本身是挂载时与每次变更后读取的宿主事实，从不跨标签页携带。

face 是宿主契约被花掉的地方。`status` 与 `probe` 是一元调用，其结果替换面板的列表或某个实例的答案。某个类型的设置描述符通过设置域已维护的设置镜像读出，保存则在表单被读取时的 revision 下，通过已绑定作用域的 `mutate` 发送暂存的操作，因此并发写入者会被发现而不是被覆盖。面板刚得知的命名空间可能不在镜像的启动答案中，此时 face 读取一次文档，并通过镜像自己的 `acceptView` 把该命名空间折回，使共享镜像始终是文档的唯一视图。标签页自己的 signal 结束它开启的每次调用，关闭的标签页不留下任何订阅。

`form.ts` 是唯一不含宿主知识的部分：它把某个类型的序列化配置 schema 变成 body 绘制的字段列表——控件种类、段落声明的选项、提供该值的层，以及字段回退到的默认值——并把读者的草稿变回设置操作，拒绝写入该字段无法存储的值。

<a id="model-experience"></a>
## 模型体验

### 远程资源配置面板

#### 模型看到什么

不直接看到任何内容。面板驱动由人拥有的 `sources` Remote 命名空间，不注册工具、提示词段落或 session 事件。它配置的内容经由资源缝隙自己的消费方——检索与读取某个源的工具——到达模型，而模型收到的文本由那些消费方拥有。

#### Token 影响

自身没有影响。面板的调用与答案不会给任何请求增加 token；它配置的源会改变那些其他消费方能返回的内容，其 token 计账由它们自己覆盖。

#### KV Cache 影响

无直接影响；此处不装配也不塑造任何模型请求。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与后续工作

- **设置命名空间是推导而来，而非声明而来。** 面板按已发布提供方遵循的约定把某个类型的命名空间拼为 `resource-<kind>`，因为缝隙不暴露「类型到命名空间」的成员。命名方式不同的提供方仍会画出其卡片，只是配置界面报告为不可达，而不是为一个并不存在的命名空间展示表单。
- **本构建不命名的类型展示其提供方自己的说明。** 面板的硬限制文案只为 GitHub、MySQL 与 MediaWiki 而写。其他任何类型原样展示提供方面向模型的 `description`，这是唯一真实的措辞；只有当提供方什么都没说时，面板才使用自己那句「限制由提供它的插件说明」。
- **secret 角色的字段会被画成普通输入框。** 宿主在描述符穿越线路前脱敏每个 `role('secret')` 值，因此面板绝不可能回显它；声明了此类字段的类型会得到文本控件而不是只写控件。已发布的资源提供方都不声明这种字段——它们改为点名一个 `dsh-credentials` 引用。
- **面板无法编辑的字段会被画出，而不是隐藏。** 嵌套对象或未声明的控件种类以其 JSON 值出现，并附一行说明此处不可编辑，因此面板未完全理解的描述符永远不会看起来像它理解的那种。
- **360AI云盘 是刻意未决的。** 面板把它列入本设计不构建的源，并报告设计所记录的内容；它不为其实作任何东西，也不就它是否应当被构建表态。开放问题见发现记录。
- **面板的设置管线与渠道面板并行。** 共享它需要一个窄的静态归属者；`form.ts` 与渠道表单的拆分方式不同且面更小，其余部分在本宿主上未做重复度测量。

### 开发备注

不发布运行时不变式伴随包：面板不拥有任何跨插件关系，它依赖的权威规则——实例 key 只对报告它的注册表解析，设置写入只对读者自己的文档解析——在 `dsh-api-sources` 与 `dsh-client-ui-settings` 中强制执行。

面板的测试套件在真实 store 实例、脚本化 Remote 与脚本化设置端口之上挂载 body，并断言读者看到的内容：读取可能落入的每种状态、每个实例一张卡片、按引用名显示的凭据、每个类型陈述的限制，以及在它读取时的 revision 下恰好发送暂存操作的保存。该标签页类型也针对右侧边栏发布的槽位声明契约做了断言。
