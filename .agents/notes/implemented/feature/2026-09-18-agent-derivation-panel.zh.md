# Agent Note：右侧栏的智能体派生面板

Status: implemented

[English](2026-09-18-agent-derivation-panel.md) | 中文

## 问题

右侧栏此前能显示会话的文件、单个文件的文本，以及它的工作状态，但没有任何地方显示它的派生。会话头部已经在一个悬停浮层里画出子代理目录，而那个界面刻意只是一瞥：它以当前会话或其父会话为根，只列出直接子级目录已经应答的内容，指针一移开就关闭。

浏览器已经持有的派生事实没有持久界面。会话列表带着每个会话（包括已经完成或已经失败的派生）及其 `parentId` 与 `origin`，Session 对象层也已经按父级镜像了直接子级目录到 `subagentsByParent`。要回答「这个会话派生了什么、还有什么在跑」，这两个事实就够了，而且都不是新的数据通路。

## 决定

`packages/client/ui-sidebar-agents` 走既有的两段式路径注册 `agents` —— 先用 `ctx.sidebarRightTabs.register({ id, kind, priority: 'builtin', visibility: 'default-on', order: 20, icon, title, guide })`，再把主体注册到该 `id` 下键控的 `sidebar.right.pane.tab` 座席 —— 这正是 [tab 类型与导航](../architecture/2026-09-05-sidebar-tab-types-and-navigation.zh.md) 那份 note 定下的机制。它是不认领任何地址的页面类型，所以[新 kind 的准入规则](2026-09-17-sidebar-task-observation-tab.zh.md)允许它成为其中一员。它是第二个声明 `default-on` 的类型，因此新面板会打开引导页、任务与派生，仍在三个的预算（`MAX_DEFAULT_VISIBLE_TABS`）之内；还剩一个名额。

面板内部有五个决定值得写明。

**树折叠自会话列表，而不是折叠自目录。** `useSessions(state => state.byId)` 给出每一个持久派生，因此已完成或已失败的子会话会与运行中的子会话并列出现，并且在任何目录被读取之前，面板说的就已经是真话。同级按列表自身的 `ids` 顺序排序，列表未排序的子级按 id 排在最后，这让顺序保持稳定，而不取决于目录何时到达。若用目录建树，面板的完整性就会取决于一次 Remote 调用。

**目录只补摘要装不下的部分。** 它们带着诊断、`hasChildren`（这一行是否还能再展开）、继续方式 `mode`，以及最关键的一项 —— 这一行到底能不能打开。面板始终观测根，并观测深度上界以内每个已展开的分支，经 `sessions.setSubagentCatalogOpen` 进行，最多三个读取同时在途；分支收起时释放该分支，面板卸载时释放全部。

**只有当所在分支的目录能确认某一行时，这一行才会打开它的会话。** `ready` 目录里的 `child` 条目是唯一的准入条件；其余每种情况都把这一行画成禁用，并写明打不开的原因 —— 目录还没读过、正在读取、读取失败、没有列出该 id、把它报成诊断，或父会话已离线。地址里的 `mode` 也取自该条目，因为摘要不带它。因此面板绝不臆造地址，也绝不打开宿主会拒绝的会话。

**目录的三种状态各自如实绘制。** 尚未读取、正在读取、读取失败（带消息与重试）各占一行，诊断是它自己的一行且禁用；只有 `ready` 目录已经应答、且会话确实没有派生时，才会说「没有派生」。把未读目录当作空，等于陈述浏览器尚未确立的事实，而这正是这个面板要避免的失败模式。

**唯一的深度常量同时约束折叠与读取集合。** `lineage.ts` 里的 `MAX_LINEAGE_DEPTH` 是唯一的界；到达它的分支画一行禁用的说明，而不是静默丢掉子级，它也不会被观测，所以递归在深度与并发上一并停止。

纯折叠是本包本地的：`session-controller/client` 与既有的世系助手都是别的包的值，而功能插件不得导入它们。头部目录把面板作为最后一条入口提供，并经由 `ctx.get('sidebarRight')` / `ctx.get('sidebarRightTabs')` 抵达它 —— 这两个是可选服务，所以没有安装派生面板时该入口就会消失 —— 同时把 kind 拼作 `agents`，即它的公开名字，因为 kind 正是这两个包唯一共享的东西。

**任务不在范围内。** 派生及其失败都不需要把 job 挂到节点上才能读，而那个挂法的形态也尚未定下；今天 job 由任务面板负责。

## 考虑过的替代方案

**只在头部浮层里加一条底栏入口。** 浮层是瞬时的、靠悬停驱动的；用户想拿运行中的链和已完成的链作对比时，走向对话记录的路上就会失去它。头部保留它的一瞥，并链接到持久界面，而不是自己长成那个界面。

**复用既有的世系助手或 `flattenLineage`。** 它们是别的包的值；跨包规则禁止该导入，而今天已经存在的那份重复（`ui-subagent` 与 `ui-workspace`）本就被记为 `jscpd:ignore` 成对项。何况这个折叠是另一个函数：它从摘要建出父子森林，而那些助手回答的是「哪些会话是这个会话的后代」。

**读遍所有目录以求完整。** 那会把 Remote 调用乘以树的大小，并让树的内容取决于可能失败的读取；会话列表本来就已经回答了存在哪些派生。

**为每一行提供动作。** 停止、继续或修复一个派生，是各自独立的决定、各自独立的命令面；一个能导航的面板足够回答它存在要回答的问题。

## 后果

只要用户留着它，侧栏现在就一直持有派生树，而头部保留一瞥式的摘要。面板是增量的：它注册的是新 kind，所以文件、文本、任务以及任何扩展 tab 都照常工作。

三个默认可见名额已用掉两个（任务与派生）。还可以有一个类型声明 `default-on`；再下一个会被注册表拒绝，直到预算变化或某个类型不再自动打开 —— 这是设计给出的信号，不是需要绕开的意外。

两条限制记在包的 README 里而不是在这里解决：深度上界用一行明确说明切断更深的树，以及 job 不挂到所属节点上。

[任务观测那份 note](2026-09-17-sidebar-task-observation-tab.zh.md) 里的任务图谱延期，就树这一层而言已由本面板定形：派生形态是「完整树来自会话列表，目录用于诊断与准入」，而每个失败的根因与每个节点的评估仍留待以后。
