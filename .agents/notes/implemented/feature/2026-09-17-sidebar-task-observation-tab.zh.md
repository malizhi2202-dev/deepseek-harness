# Agent Note：右侧栏的任务观测 tab

Status: implemented

[English](2026-09-17-sidebar-task-observation-tab.md) | 中文

## 问题

右侧栏此前只有两种 tab 类型 —— 工作区文件树（`@deepseek-ai/dsh-client-ui-sidebar-files`）与只读文本预览（`@deepseek-ai/dsh-client-ui-sidebar-textpreview`）—— 外加 该面板自己的引导页。浏览器已经持有的会话工作状态在那里没有任何界面，因此要回答"这个会话在做什么、还剩下什么"，只能去翻对话。

两个事实本来就已经活在浏览器里：宿主计算出的 `todos` 会话投影，以及 Session 对象层的 `jobsBySession` 镜像。侧栏里没有任何东西读它们。

## 决定

`packages/client/ui-sidebar-tasks` 通过那套既有的两段式路径把 `tasks` 注册为第三种 tab 类型 —— 先用 `ctx.sidebarRightTabs.register({ id, kind, priority: 'builtin', title, guide })`，再把主体注册进键控座席 `sidebar.right.pane.tab`、键为该 `id` —— 并在同一个主体里画这两个事实，不带 store、不带 face、不发请求：`useProjection('todos')` 与 `useSessions(state => state.jobsBySession[sessionId])`。两者都不是新的数据通路，所以这个面板没有任何需要失效的状态，也没有会失败的 Remote 调用。注册表与座席是[tab 类型与导航](../architecture/2026-09-05-sidebar-tab-types-and-navigation.zh.md)那条笔记定下的机制，而这个包是它的第三个消费者。

主体内部有四个决定值得写下来。

**清单按模型写入的顺序绘制，而不是按状态分组。** `todo/write` 携带的是完整列表，条目本身没有身份，所以模型的顺序就是计划；按状态重新分组会破坏这个次序。因此一行的键由位置与文本共同构成，而聚合视图放在标题行 —— 针对同一份清单的一个计数加一条进度条。

**面板只观测，从不动作。** 面板里没有任何东西能改一条待办或停掉一个任务；这类动作本来就属于对话或那个任务自己的界面。这也让主体不需要 owner 的动作，因而它也不注册 store。

**进度槽用的是 `--dsw-alias-bg-layer-1`，不是抬升的 `-2`。** `ui-theme` 的滚动条审计会让任何"会滚动、却引用了抬升表面又没重新绑定"的样式表失败，因为在暗色配色下滚动条滑块所用档位与那个表面只在那一处不同。这个面板自身的表面是透明的，所以把滑块重新绑到 l2 档等于对这个表面说了假话；用基础档才是诚实的做法，而审计自己对"抬升集合"的定义也把它排除在外。

**这个 tab 是不认领任何地址的页面类型，并声明 `visibility: 'default-on'`、order 10 与自己的 `icon`，** 因此新停靠面会在引导页旁自动打开它，tab 条的类型选择器也把它排在第一个（[默认可见集](../architecture/2026-09-17-sidebar-right-default-visible-set.zh.md)）。顺序为 20 的引导页条目保留，用户关掉它之后由此找回。`ui-sidebar-right` 里不需要有任何代码知道这个包的存在。它作为核心 `web-app` 的一行被组合进去，而不是作为 profile 本地插件，这正是它能对每个 Web 部署可用的原因。

## 考虑过的替代方案

**在对话里放一个区块。** 这些事实是关于整个会话而不是某一轮次的，而对话已经是窗口里最长的界面；放在侧栏 tab 里能让它们与对话并列，而不是塞进对话。

**复用文件树的 store 与 face 拆分。** 那个拆分之所以存在，是因为文件树要保存每个 tab 的展开状态并经 Remote 逐层列出。这个面板两者都不需要，照搬那个拆分只会多出一个主体从不写入、也从不调用的 store 与注入 face。

**抬升的进度槽加一次滚动条重绑。** 这满足审计的字面要求，却不满足它的意图：面板并不是抬升表面，重绑出来的 l2 滑块在每一套配色下都是错的。

**通过投影而不是镜像读取任务。** 并不存在任务投影；Session 对象层已经为会话头部的动作按会话镜像了任务，再做一次投影等于把同一批记录发布两遍。

## 后果

侧栏现在不用离开窗口就能回答会话进度的问题，而且这个面板是增量的：它注册的是一个新 kind，所以文件树、文本预览（[已有的两种类型](2026-09-05-sidebar-text-preview-and-file-tree.zh.md)）以及任何扩展 tab 都照常工作，对它们而言 tab 集合没有变化。

两条限制记在包的 README 里而不是在这里解决：面板只观测，且它只报告状态、不含任务时间，因此暂时不需要时长格式化。

`todos` 投影按模型写入的原样绘制，所以模型从不调用待办工具的会话会显示空状态，而不是一个推断出来的计划。本 note 延期的、基于子代理世系的**任务图谱**，现已由[智能体派生面板](2026-09-18-agent-derivation-panel.zh.md)定形：树折叠自会话列表，目录只提供诊断与准入。每个失败的**根因**与对每个节点的**评估**仍然延期。
