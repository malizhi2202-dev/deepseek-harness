# Agent Note: 发现路径拒绝未声明的线协议

Status: implemented

[English](2026-09-17-discovery-refuses-undeclared-protocol.md) | 中文

## Problem

对已安装目录未描述的路由，模型发现会去问端点 `GET {baseURL}/models`，而线协议决定了该请求的头、它的列举 URL，以及回复到底能不能解析。一个没有点名协议的发现请求照样发出去了，按 `openai-completions` 发问，而代码把这个选择写成一次猜测：Anthropic 网关对 completions 探测回 401，「读起来像凭据问题」。

一次猜测带出两处缺陷。探测把每一个说别的协议的端点都指错了方向，而失败提示又叫这次指错更难纠正：401 或 403 响应会无条件追加 `check the API key`，于是操作者被打发去复查一个从来不是原因的凭据，而真正的错因不留任何痕迹。本包自己的 README 早已要求 pi-ai 不发的路由必须给出 `api`、`baseURL` 和非空 `models` 列表，因此发现路径违背了它自己所在包已记载的要求。

## Decision

`discoverModels` 拒绝没有点名协议的请求，在任何东西发出之前就拒绝，报 `DISCOVERY_UNSUPPORTED`，消息里点明缺失的字段、本构建能问的协议，以及手工录入这条剩下的出路。协议是调用方唯一拥有的输入，因此该路径不再替它替换一个。由于拒绝发生在网络之前，同一段代码同时覆盖了调用方必须补上的请求形缺与模块自己负责的请求形缺。

401 或 403 的列举被拒现在同时点名两个候选，而不是对第一个下定论：`check the credential, and that api "<api>" is the wire protocol this endpoint speaks`。端点拒绝的凭据与声明协议错误的路由在该状态码下表现完全相同，因此该消息止步于断言其中是哪一个。其他状态码照旧不带提示。

`LISTABLE_PROTOCOL_NAMES` 是本包内对「本构建能为其列举模型的协议」的唯一声明；`LISTABLE_PROTOCOLS` 是它的成员测试，`listableProtocols()` 为各条拒绝把渲染出来。`provider.ts` 里的 `PROTOCOLS` 拥有该适配器能说的线协议，本列表是其中带模型列举端点的子集，该常量的 JSDoc 写明了这一点。

请求类型与设置页都没有改动。`LlmModelDiscoveryRequest.api` 在词汇表里保持可选，因为目录已经能回答的路由不需要协议；只有当请求真的去问端点时才要求该字段。模型设置页的自定义 provider 卡片本就带协议选择器并把它作为 `api` 传下去，因此已经选好协议的操作者不受影响。

## Alternatives considered

**保留默认值，只修提示。** 这会把探测本身留在指错的状态：说别的协议的端点照样被问错的问题，操作者照样是通过一次失败才得知，而不是通过本可提前点名协议的那个请求。它也让代码继续违背本包 README。

**把凭据提示的条件设为「协议已被显式声明」。** 拒绝落地之后，未声明的协议再也到不了这条拒绝分支，因此每个走到这里的请求都会满足该条件，提示实际上仍是无条件的。声明本身也可能是错的，而那正是这条提示所误述的情形。

**探测端点以得知其协议，或在失败后改换另一协议重试。** 被端点判为坏请求的请求换任何协议都只会复现自己并埋掉真因；协议不匹配不是 failover 的触发条件，而「靠探测落定协议」不是任何已调研网关或规范提供的模式。把协议在请求之前定下来，保证了每次问询一个请求、每条诊断一个原因。

**把 `LlmModelDiscoveryRequest` 里的 `api` 改为必填。** 那样该类型会向从不问端点的目录路由、以及手里没有协议可给的调用方索要协议。拒绝应当发生在真正去问端点的地方。

## Consequences

没有选好协议的草稿路由在选好之前无法发现模型。这是有意的代价：动作被从一个只剩一个字段要填的调用方那里收回，而拒绝说清了是哪个字段、接受哪些取值。模型设置页的协议选择器就是这条拒绝所指向的答案。

401 与 403 的提示不再断言凭据是原因，因此一个凭据确实写错的操作者会被要求考虑两个候选而不是一个。这个取舍是刻意的：写错的凭据一试就能自我显明且可恢复，而写错的协议曾导致一场无法收敛的排查，两者却共用同一个状态码。

根子上的指错是被削弱而不是被消除。声明协议错误的路由依旧失败，它的提示现在点名了这种可能而不是把它分辨出来；发现路径里没有任何东西能核实端点是否在说它路由声明的协议。`LISTABLE_PROTOCOL_NAMES` 与 `PROTOCOLS` 仍是两份声明加一句写明的关系，而不是一份派生出另一份，因此将来往其中之一加了协议而没加另一个，仍会静默漂移。

## Testing

`packages/llm/llm-pi-ai/tests/discovery.spec.ts` 以断言其消息与 `DISCOVERY_UNSUPPORTED` 码两者覆盖了这条拒绝，并断言 401/403 的提示点名了已声明的协议、而服务端故障两条都不点名。该 spec 中每个真的到达端点的请求现在都显式点名其协议；该 spec 的目录用例依旧不传协议，并且依旧从目录解析。该文件保持语句、分支、函数、行四项 100% 覆盖率，该包的 13 个 spec 文件全部通过。
