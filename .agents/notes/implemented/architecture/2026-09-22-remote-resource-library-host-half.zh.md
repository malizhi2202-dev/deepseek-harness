# Agent Note: 远程 resource 库的 Host 半边

Status: implemented

[English](2026-09-22-remote-resource-library-host-half.md) | 中文

## Problem

部署方自己的知识存放在 harness 无法触达的集合里：wiki、代码托管、数据库。web seam 用检索索引中的文档回答一次检索查询，文件系统 seam 回答单个工作区内的路径；两者都无法寻址某个 wiki 的某一页、某个仓库的某个文件，或某个数据库的某张表。[resource 库设计](../../../../discovery/remote-control-and-sources-2026-09-21/04-resource-library-design.md)冻结了第三种访问的词汇，并给出了波次划分：本次变更实现 Host 半边——seam、三个提供方与面向模型的消费方——而 `sources` 面板及其 Remote 命名空间属于另一次变更。

该 seam 必须服务三种几乎毫无共识的协议。wiki 以标题寻址页面，并以 snippet 回答全文检索；代码托管以 `owner/name:path` 寻址文件，在请求配额下检索代码，且对约一兆字节以上的内容不返回内联内容；数据库以标识符寻址结构，完全没有全文检索，并且是三者中唯一一旦语句写错就会造成破坏的。因此该词汇只归一化调用方所做的动作——检索、读取、列表——而把寻址、限制与失败文本留给拥有该 kind 的提供方。

## Decision

`packages/resource/` 下的五个包：`@deepseek-ai/dsh-resource`（Service Definition 与 `ctx.sources` 注册表）、`@deepseek-ai/dsh-resource-mediawiki`、`@deepseek-ai/dsh-resource-github` 与 `@deepseek-ai/dsh-resource-mysql`（提供方），以及 `@deepseek-ai/dsh-tool-resource`（消费方）。该 seam 在本仓库对 capability seam 要求的三种角色上都是完整的，每个提供方以自身 fiber 上的 effect 形式注册。

**kind 声明自己能回答什么。** `capabilities` 携带 `search`、`browse`、`read`、`maxReadBytes`、`maxListItems`，以及面向模型的 `description`，后者陈述该 kind 的限制。只有当某个 kind 声明了该能力、实现了该方法、且至少有一个已配置实例时，它才会贡献一个工具，因此模型永远不会看到无法工作的工具。

**每种 kind 一个设置命名空间，密钥按名称引用。** 每个提供方从 `resource-<kind>` 读取其实例，并在每次操作时通过 `dsh-credentials` 解析 `passwordRef` 或 `tokenRef`，因此轮换后的密钥会在下次调用生效，且配置中不含任何密钥值。不会出现新的持久化域：`dsh-settings` 已拥有命名空间段，且其文件提供方会持久化它们。

**MySQL 由分类保证只读。** 每条语句都经过同一个查询入口，该入口只接受 `SELECT`、`SHOW` 与 `DESCRIBE`，拒绝第二条语句，并拒绝形如读取但实际写入或加锁的语句。被拒绝的语句在调用会话之前即抛出 `SOURCE_DENIED`。在更底层，连接器设置 `SET SESSION TRANSACTION READ ONLY`，从不启用多语句，并假定账号只持有读权限。标识符来自配置的授权文本，绝不来自模型的句柄，且服务器报告但配置未授权的库保持不可见。

**GitHub 默认拒绝。** 实例声明它授权的仓库；检索为每个已授权仓库携带一个 `repo:` 限定词，命中在返回途中会再次过滤；对列表之外任何内容的读取或列表会在发出请求之前以 `SOURCE_NOT_FOUND` 失败。Octokit 以 `redirect: 'error'` 构造，因此令牌无法被转发到其他源。

**冻结设计需要八处修正，这里如实记录而非静默处理。** 提供方接口新增了 `instances()`，因为设计中的 `Sources` 无法枚举工具描述必须列出的已配置实例。`SourceCapabilities` 新增了必需的 `description` 与 `maxListItems`，因为设计中的 `list` 不携带调用方上限，其 `SourceHit` 也不携带截断信号；列表上限从按实例改为按 kind，以便可被声明。按本仓库对不透明跨边界 id 的规则，`SourceItemRef` 是 brand 句柄而非裸字符串。注册表发布 `sources/changed` 事件，这是设计中不存在的，因为派生出的工具集必须跟随设置编辑。`register()` 返回普通 disposer，因为设计中的 `Disposer` 类型在 vendored cordis 中并不存在。kind 名必须匹配小写语法，因为它会成为工具名的一段与设置命名空间的一段。并且不注册 `dsh-resource://<source>/` 地址域：路线图曾提议它，而冻结设计给该面板的页面类型不声明地址，因此本次变更实现设计并记录该冲突。

**依赖。** 采用 `@octokit/rest` 22.0.1 与 `mysql2` 3.24.4，因为本仓库倾向于使用受维护的客户端而非手写传输层，且它们各自删除了本会成为自有代码的请求构造、响应解析与连接处理。

## Alternatives considered

**一个用 URL 模板配置的通用 HTTP 提供方。** 否决：三种 kind 在寻址、限制的含义以及模型必须能据以行动的失败上各不相同，模板提供方会把协议知识挪进配置，并失去那些让不可用工具保持未注册的已声明能力。

**复用 web seam。** 否决：web 检索返回的是检索索引中的文档，没有稳定句柄；而 source 回答结构化句柄，并支持读取某个具名条目。把它们合并会把同一套提供方选择策略强加给需要各自配置的集合。

**注册所有操作，在调用时失败。** 否决：无法工作的工具会在每次请求中消耗 token，并让模型不再信任这套工具。有条件派生正是让已注册集合保持诚实的原因。

**让模型直接发送 SQL。** 否决：没有白名单能约束模型写出的内容，而真正要紧的正是破坏性场景。提供方只发出某张已授权表的投影并带行上限，检索则在不发出任何语句的情况下匹配已授权名称。

**把密钥保存在设置段中。** 否决：设置段可被读取、导出，并会显示在配置界面上。只有凭据名进入配置，值则逐次操作解析。

**为 source 配置新增持久化域。** 否决：`dsh-settings` 已拥有带文件提供方的命名空间段，第二个存储只会让某个实例的配置多一处可能出错的地方。

## Consequences

- **部署方自行选择 kind。** 仅挂载 seam 不会注册任何工具，也不会让任何内容对模型可见；部署方每挂载一个提供方，就会在其拥有已配置实例后增加相应工具。
- **模型可见文本是派生的，因此会随设置变化。** 改变实例列表或限制说明的设置编辑会重写请求前缀，而不只是模型可传入的参数。这一点记录在消费方的「已知限制」中。
- **工具集以模型可观察的方式有条件存在。** 新增提供方会增加工具，而失去最后一个已配置实例的 kind 会失去这些工具，无需任何重新挂载。
- **写入由分类拒绝，且测试通过入口证明这一点。** 拒绝测试用一个必须保持空的记录型会话驱动查询入口，因此证明覆盖的是做出该决定的操作，而不是它旁边的一个辅助函数。
- **未对三个后端中的任何一个发出真实调用。** 这里没有 GitHub 令牌、没有 MySQL 服务器，也没有 wiki。每个测试套件都驱动桩传输：桩 Octokit 客户端、注入的 `mysql2` 驱动，以及注入的 MediaWiki 交换层。重定向策略通过在桩化的全局 `fetch` 上断言 `redirect: 'error'` 初始化项与认证头来钉住，真实的 `mysql2` 适配器则针对一个关闭的回环端口执行一次，并如期失败。
- **`pnpm run duplication` 无法在本主机运行。** 固定的 jscpd v5 二进制需要 GLIBC 2.32 或更新版本，而本主机提供的是 2.31，因此本次变更不记录任何重复度结果。
- **规范覆盖率命令目前无法运行。** `tsconfig.base.json` 生成的 `paths` 区域在集成时运行 `pnpm run gen-tsconfig-paths` 之前不含这五个新别名；各套件通过带显式别名的等价临时配置运行，父级必须重新生成并重跑规范命令。

## Testing

`packages/resource` 在 14 个文件中共有 189 个测试，五个包的每个源文件在语句、分支、函数与行上均达到逐文件 100%。seam 的套件在精确与极小上限、以及多字节预算下钉住字节边界，钉住注册表的 kind 语法、其 kind 重复失败、加入与销毁时的变更事件，以及「提供方及其事件监听器已消失」的 fiber 销毁证明。MediaWiki 套件钉住 wire 守卫、登录与匿名路径、cookie jar 与重定向策略。GitHub 套件钉住响应守卫、检索与内容的请求构造、两个方向上的授权列表过滤，以及桩化 `fetch` 上的重定向与认证事实。MySQL 套件钉住语句白名单的接受集与拒绝集、通过查询入口驱动且记录型会话保持为空的拒绝证明、在任何语句存在之前即被拒绝的注入标识符、三层列表、行与字节截断，以及失败时的会话关闭。消费方的套件钉住每种能力与方法组合下的有条件派生、两次变更重叠时的串行重新派生、按该 kind 上限渲染的边界，以及「该 fiber 的工具已注销」的销毁证明。
