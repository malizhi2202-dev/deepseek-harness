# Agent Note: 工作区自动化台账的读取与面板

Status: implemented

[English](2026-09-22-workspace-automation-ledger-read-and-panel.md) | 中文

## Problem

[定时器与提交设计](../../../../discovery/workspace-git-alignment-2026-09-21/02-timer-and-commit-design.md)给工作区自动化运行时留下了一份已存台账，并要求在其上做一个面板：对每次运行说明比较了什么、这次运行做了什么或为何没做、冲突在哪里、接下来会怎样（§7.4）。[运行时半边](2026-09-22-workspace-git-alignment-and-automatic-commit.zh.md)——调度器、对齐与提交任务、挂起与退避规则——把这一切都记录了下来，但没有任何东西把它投影到浏览器，因此一条已记录的运行只有打开会话日志的人能读到。

该要求的两个性质决定了形态。失败路径正是这类面板通常会退化的地方：一次被取代、跳过被锁工作区、或拒绝提交的运行，恰恰是读者最需要解释的情形，而对这些情形渲染一张空卡片，按设计自己的度量就是缺陷而非外观瑕疵。而且台账对"某次运行做了什么"是权威的——一次运行的比较涉及的是运行时当时观察到的提交，而非仓库现在的读数——因此从 git 重建这套账的面板会报告与真实发生过的历史不同的历史。

## Decision

两个包，镜像 channel 与资源库两对包。`@deepseek-ai/dsh-api-workspace-automation` 拥有**共用的 `workspace` Remote 命名空间**中的一个方法：`automationLedger(workspaceId)` 返回已记录的台账或 `unrecorded`，其内容投影自 `ctx.workspaceAutomation.report(workspaceId)`。`@deepseek-ai/dsh-client-ui-sidebar-automation` 把 `automation` 注册为右侧栏的标签类型——`order: 800`、`visibility: 'available'`、一个不占用地址也不声明任何模式的页面类型——其主体绘制工作区状态与全部保留的运行。

**该方法加入 `workspace` 命名空间，而不是另开一个。** 两个读取都以同一个不透明 `WorkspaceId` 为键，客户端在绘制工作区界面时已经握有该键，而一个平级命名空间会让一个概念在客户端装配里拥有两个命名空间键。代价是真实的，并且立刻付出了：命名空间生成的客户端类型迫使每个顶替 `remote.workspace` 的测试替身都实现这个新成员，于是 `api/workspace-controller` 与 `api/session-controller` 里的四个替身以"未使用即抛错"的方式实现了它。因此部署中的命名空间到服务映射并非一一对应，任何假定如此的生成目录都需要注意这一点。

**投影是纯的，端点不持有状态。** `projection.ts` 抄写已存的值、把每个列表裁到其界限、把保留的运行按最新在前排序，并从设计的结果表读出下一步。不从 git 重算任何东西，也不缓存任何东西：一次重新读取就是再次询问运行时，因此某人刚刚清除的挂起会被报告为已清除。

**每个界限都是经校验的 `Config` 字段。** `maxRuns`（默认 20）界定一次读取返回多少条运行，`maxPaths`（默认 10）界定每个路径列表——运行的冲突路径、它拒绝或无法归属的路径、提交的路径，以及上次提交任务报告的未提交余量。每个有界列表都带着被裁剪前的计数跨线，读者因此知道界限藏起了什么，而不是默默看到一份短列表。

**每次运行都按设计的顺序回答设计的四个问题。** 比较问题绘制 `baselineBefore` → `observedUpstreamOid`，并在运行记录过时附上期望的 head 与新的基线；结果问题为每个结果变体绘制一句话，并附上已提交运行创建的提交；路径问题绘制该运行自己的列表；下一步问题绘制设计表为该结果指派的步骤。`lines.ts` 为每个变体、每个下一步、以及一次失败的读取各持一个函数，各自按其判别式穷尽 switch，因此运行时新增的结果会先在宿主包编译失败，而不会渲染成一张没有解释的卡片。

**面板只读，唯一的控件就是一次读取。** 定时器由工作区注册表与自身配置武装（§八把武装、暂停与排期编辑留在面板之外），因此这里没有启用、停用、重试、立即运行或排期控件；一个不可能起作用的控件比它缺席更糟。它确实有的是工作区拼接：台账不携带路径或标题，因此主体通过客户端工作区模型解析会话的工作区并绘制两者，而没有已注册工作区的会话会如实说明，并且不向宿主索取任何东西。

## Alternatives considered

**另开一个 `workspaceAutomation` 命名空间。** 否决：两个读取回答的是同一个 `WorkspaceId`，而客户端的激活边两种做法下都一样——它为某个具名服务挂载一份生成的 remote。第二个命名空间还得加入客户端装配的挂载列表，而这次改动的代价本来也正是在那里付出的。共用命名空间的实测代价是上面那四个测试替身；平级命名空间的实测代价会是在每个已经手握工作区 id 的消费方那里，为一个概念增加第二个键。

**从 git 状态重建这套账。** 否决：一次运行的比较记录的是运行时在那次运行期间观察到的提交，而仓库之后还会变。重算会报告一次从未发生过的比较，并让面板与人在同一时刻读到的台账互相矛盾。

**持久化面板自己的视图。** 否决：台账是权威，运行时是它唯一的写方。存一份副本需要运行时并未发布的失效规则，而面板的整个读取只是一次调用。

**在面板里界定运行列表。** 否决：界限必须施加在值离开宿主的地方。面板侧的裁剪仍会把整份台账放上线路，响应还会随运行时自身配置设定的保留环增长。

**提供一个立即运行控件，让人能对所见的采取行动。** 否决：设计把每个武装决定都留给工作区注册表，而手动触发不在本波范围内。该发现属于设计，而不属于面板无法兑现的控件。

**通过读取仓库来绘制每个保留的提交。** 否决：台账已经携带提交的 oid、主题、正文、摘要来源以及是否仍可撤回，再做一次读取会让面板的账依赖于仓库的当前状态，而不是运行当时记录的内容。

## Consequences

- **台账的 observed upstream id 是本地 head，面板以不改名的方式如实呈现。** `RunRecord.observedUpstreamOid` 由对齐任务在 fetch 之后写入，值是它观察到的本地 `HEAD` oid；`ctx.git.observe` 不报告任何上游提交 id，`gitAlign.fetch` 也只回答发生过一次 fetch。投影按该字段自己的名字携带台账的值，不对上游尖端作任何断言；宿主 README 记录了这一点，而指名上游尖端需要一个 git 缝隙并未发布的 oid。
- **有些路径列表不带真实总数。** 拒绝与归属不明的列表在到达之前已被运行时的 `maxPathsPerCommit` 裁过，因此旁边报告的计数是台账持有的长度；只有冲突的列表与提交的路径列表带总数。面板的文案因此读作"另有 N 条未展示"，这对每个列表都成立，而不是"还剩 N 条"。
- **两个生产者侧的列表无界。** 上次提交任务的 `uncommittedPaths` 与归属不明的路径到达时没有界限；本投影正是给它们加界的一方，而一次指名了上千条路径的运行仍会让整份列表上线路。
- **运行界限的默认值是产品选择。** `maxRuns` 默认为 20，而设计的保留数字是 200 条环形缓冲；台账自身的计数绘制在返回的运行旁边（`runs.bounded`），因此界限是可见的而非静默的，想要整份保留台账的部署在 `cordis.yml` 里调高它。
- **台账缺的值，面板补不上。** 凡是面板想要而台账没有的值——上游尖端、被截断列表的真实总数——面板就绘制它手上的内容。其已知限制逐条列出这些缺口，而不是推导一个替代品。
- **两半通过生成的客户端一起移动。** 面板读取 `remote.workspace.automationLedger`，其类型来自宿主包的生成产物；宿主侧对结果联合的改动会让面板编译失败，而不是在运行时才被处理。
- **留给父级发布的接线。** 两个聚合现已携带这两个包。本次改动之外仍待完成的是 Web bundle 的 `dsh.client` 行与依赖条目，以及把本宿主包生成的 remote 客户端与 Workspace Controller 的一同挂载进客户端装配。
- **未运行 `pnpm run duplication`。** 固定版本的 jscpd 二进制需要 GLIBC 2.32，而本宿主提供 2.31，因此对投影与面板都不主张任何重复率结论。

## Testing

`packages/api/workspace-automation` 有 12 个测试，`packages/client/ui-sidebar-automation` 有 6 个文件共 49 个测试，两者对每个源文件都达到语句、分支、函数、行 100%。

端点的套件在脚本化运行时之上构建该服务，并固定整个投影：未记录的工作区、被抄写的状态、带台账自身计数的最新在前排序、极小与恰好相等的界限，以及每个结果变体各一例并附设计表指派的下一步——包括什么都没做的那些变体，而设计可解释性度量的真正考验正在那里。它还直接覆盖纯投影函数，因此界限或排序的回归无需 Remote 调用就会失败。

面板的套件在真实的 store 实例、脚本化 Remote 与脚本化工作区 hook 之上挂载主体，断言读者看到的内容：加载、失败、未记录与已记录状态；没有工作区的会话；每个结果变体（包括 `superseded`、`skipped-locked` 与 `refused`）都具备且按设计顺序排列的四个问题；路径及其装不下的计数；以及一次真的再次询问宿主的重新读取，同时更早的读取无法覆盖它。标签类型也会对照右侧栏发布的槽位声明契约断言。
