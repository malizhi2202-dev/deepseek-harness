# Agent Note: 远程资源库的面板半边

Status: implemented

[English](2026-09-22-remote-resource-library-panel-half.md) | 中文

## Problem

[资源库设计](../../../../discovery/remote-control-and-sources-2026-09-21/04-resource-library-design.md)冻结了触达部署自有集合——一个 wiki、一个代码宿主、一个数据库——的词汇，并切分了波次：[宿主半边](2026-09-22-remote-resource-library-host-half.zh.md)交付缝隙、三个提供方与面向模型的消费方，而人用来让某个源真正可用的配置界面属于另一次变更。没有该界面，缝隙只能靠手工编辑设置文档触达，而配置错误的源会向模型报告自己不可用，GUI 里却没有任何东西说明原因。

该界面必须回答缝隙不回答的三个问题，且不能变成第二个事实来源。有哪些实例存在是提供方自己的答案，而一个类型可以声明多个实例，因此实例需要一个能在设置编辑后继续成立的身份。实例是否已配置同样是提供方的答案，而源本身不建立连接，因此面板没有任何激活状态可移动。凭据只被点名、绝不被内联，因此面板必须展示某个名称是否解析成功，同时绝不持有值——这条规则是设置提供方的密钥脱敏覆盖不到的，因为凭据引用并非以 secret 声明。

## Decision

两个包，镜像已经解决同一形态的聊天渠道对。`@deepseek-ai/dsh-api-sources` 拥有 `sources` Remote 命名空间：`status` 报告注册表服务的每个实例，`probe` 测试其中一个。`@deepseek-ai/dsh-client-ui-sidebar-sources` 把 `sources` 注册为右侧边栏标签页类型——`order: 700`、`visibility: 'available'`、一个不认领地址也不声明 pattern 的页面类型——其 body 绘制列表、每个实例的状态、其凭据引用、由该类型自身 schema 推导的设置表单，以及该类型的硬限制。

**实例以 `kind/id` 寻址，且该 key 是不透明的。** `status` 答案携带 `key`、`kind`、`id` 与设置命名空间；此后每次调用都点名 key，从不解析它。面板的 store 以该 key 保存每实例记录——最近一次探测、最近一次控制失败、已暂存的草稿——因此一个类型声明两个实例时，两份表单与两个结果彼此分开，重新加载也会把每个实例的记录带过去。

**面板推导状态，而不是拥有状态。** `unconfigured` 是提供方自己的 `configured: false`；`unchecked` 是已配置但尚无探测在该类型当前设置 revision 下观察过的实例；`usable` 与 `unusable` 来自本进程观察到的最近一次探测。探测之后被编辑的实例重新读作未检查，因为该结果描述的是已不再成立的设置，而一次失败不会被之后的成功清除。不存在启用或停用，因为设计从「是否已配置」推导源是否连接，而无法生效的控件不得被提供。

**凭据引用以结构化方式发现，并以名称报告。** 设置提供方把 schema 发布为 JSON，其中嵌套节点要么内联、要么是共享 `refs` 表中的下标，而 `redactSecrets` 覆盖 `role('secret')`、却从不覆盖 `role('credential-ref')`。因此端点沿凭据引用可被声明的容器下行——`object`、`dict`、`array`、`intersect`——收集声明该角色的字段，并从提供方自己解析出的实例上读出每个字段的值。它报告引用名、其背后是否存有值、该值来自哪一层，以及本宿主是否可写它；不是引用名的值以未设置报告，而不是被悄悄略去。

**设置命名空间由提供方约定推导。** 每个已发布提供方把自己的命名空间命名为 `resource-<kind>` 并从其中解析实例，而缝隙不暴露「类型到命名空间」的成员，因此端点自行拼出该名称。命名空间注册方式不同的类型仍会报告其实例，其配置界面读作不可用，而不是为一个并不存在的命名空间渲染表单。

**缝隙是本地镜像，而非被依赖。** 本波次不得新增任何依赖，因此 `packages/api/sources/src/seam.ts` 重述了端点消费的提供方契约——类型、能力、配置、描述，以及注册表的两个读取——并刻意省略面板从不调用的操作（`search`、`read`、`list`）。把 `@deepseek-ai/dsh-resource/types` 取为 devDependency、引用其项目，并用一次纯类型导入替换该镜像，就是全部改动；端点已经是针对这些名字写的。

**设计刻意不构建的源连同其理由陈述，且没有任何控件。** 360云盘、网易云盘、夸克云盘与百度云被列在一个可折叠区块中，附带记录对每一个的说法，并点名 WebDAV/S3/本地挂载这一替代路径。360AI云盘被列为未决：设计记录与请求记录就它是被排除还是被留作开放问题互相矛盾，因此面板报告本波次不构建它，且不表态。

## Alternatives considered

**以类型作为实例的键。** 拒绝：一个类型可以声明多个实例，那样两个实例会共用一份表单、一个探测结果和一个 React key。渠道面板可以按类型作键，因为一个渠道就是一次绑定；一个资源类型则是一组实例。

**通过直接读取设置段落来报告源的配置。** 拒绝：段落持有的是人输入的引用*名*，而提供方持有的是它解析出的值——包括组合层与未设置字段回退到的默认值。读取段落会报告一个提供方从未解析的引用，并把对配置的第二种解释放进面板。

**从端点自己对 schema 的看法渲染表单。** 拒绝：设置域已经发布每个命名空间的描述符，带其分层、revision 与已绑定的写入作用域，且其镜像与设置面板共享。从描述符推导行，可让文档只有一个读取者，并使本构建从未听说过的类型也得到一份表单。

**展示凭据的值以便人确认。** 拒绝：设计禁止内联密钥，而渲染它的面板会把它放进 DOM、放进截图、放进页面的任何导出。存在性、来源与可写性已经回答了人真正关心的问题。

**为每个源提供启用与停用。** 拒绝：设计从配置推导连接，这样的控件会写入没人读取的状态。将来增加激活域的波次可以加上该控件。

**复用渠道面板的表单模块。** 本波次拒绝：两个包是两个独立特性，特性插件不得运行时导入另一个插件的值，而把共享部分提升为静态归属者需要本次变更没有的签字。资源表单的拆分方式不同，覆盖面也更小。

## Consequences

- **本构建不命名的类型仍可配置。** 表单来自描述符，标签回退到类型本身，因此部署挂载的提供方无需改动此处就能得到可用的卡片。其硬限制以提供方自己面向模型的 `description` 展示，这是唯一真实的措辞；面板自己的限制文案只为 GitHub、MySQL 与 MediaWiki 而存在。
- **有一处耦合是猜的，并且会显性降级。** `resource-<kind>` 命名空间约定并非由缝隙声明，因此命名方式不同的提供方会失去表单。修复属于缝隙——在 `SourceProvider` 上增加 `settings` 或 `namespace` 成员——并记录在端点的已知限制中。
- **探测结果只存活于进程内。** 重启后每个已配置实例都读作未检查，直到有人再次探测；设计没有为它们增加持久域。
- **面板的设置管线与渠道面板并行。** `form.ts` 的拆分方式不同、面更小，其余部分未做重复度测量：`pnpm run duplication` 在本宿主上无法运行，因为固定的 jscpd 二进制需要 GLIBC 2.32，而本宿主提供 2.31。不声称任何重复度结果。
- **两个新包需要父级接线。** `packages/api/sources` 需要其宿主聚合引用、其 `tsconfig.base.json` 别名，以及把其 Remote 服务挂进客户端装配；`packages/client/ui-sidebar-sources` 需要其 `tsconfig.client.json` 引用、其别名、Web bundle 补丁层中的一行 `dsh.client`，以及该 bundle 的依赖条目。在这些落地之前，客户端聚合会把该包的文件报告为不在其项目文件列表内。
- **生成的 Typert 产物是构建残留。** `lib/typert.host.*` 与 `lib/typert.remote-client.*` 是用临时宿主配置产出的，因为该包尚未进入规范聚合；父级必须在接线后通过仓库生成器重新生成它们。

## Testing

`packages/api/sources` 有两个文件共 34 个测试，`packages/client/ui-sidebar-sources` 有六个文件共 76 个测试，两个包的每个源文件都达到逐文件 100% 语句、分支、函数与行覆盖。

端点的测试套件驱动脚本化提供方、设置描述符与凭据事实。它们固定：每个已声明实例一个视图，类型与实例各自按注册顺序；线路视图的最小 key 顺序；四种状态各自的推导，包括探测之后发生变化的 revision 与之后的成功未能清除的失败；以及针对手工构造序列化 schema 的凭据遍历，覆盖扁平根对象、实例字典、intersect、array、嵌套对象、无法解析的引用，以及不是引用名的值。探测用例固定：提供方收到的是它自己解析出的实例；未知 key 以 `sources/unknown` 穿越；拒绝以值作答。

面板的测试套件在真实 store 实例、脚本化 Remote 与脚本化设置端口之上挂载 body。它们固定：读取可能落入的每种状态；每个实例一张卡片；按引用名而绝不按值显示的凭据；每个类型陈述的限制，包括本构建不命名的类型；在它读取时的 revision 下恰好发送暂存操作的保存；未落地而保留草稿的保存；以及不提供任何控件的缺失源区块。该标签页类型针对右侧边栏发布的槽位声明契约做了断言，且 `verify-sidebar-right-tab-types` 报告 `sources` 位于 order 700、为 available 页面类型。
